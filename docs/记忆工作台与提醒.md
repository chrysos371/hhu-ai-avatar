# 记忆工作台、反馈与提醒

2026-11-10：当前页面已由 [Mission Control 后台](Mission-Control后台.md) 替代，构建 React 前端后再启动。新版手动变更走草案与审计，到期提醒页面轮询间隔为十秒。下文保留原后端与CLI行为说明，旧网页直接写接口仅限兼容模式。

## 启动

在项目根目录执行：

```powershell
python start_web.py
```

打开终端输出的完整链接（包含 `#` 后的临时访问凭据）。默认端口 8765，只有本机 `127.0.0.1` 可访问。换端口或临时数据库：

```powershell
python start_web.py --port 8766 --db ./data/demo.db
```

页面含文本对话、当前角色情绪与活跃度、长期记忆、来源详情、历史版本、纠错、彻底删除、召回不相关反馈和提醒管理。不需要前端构建或 CDN。刷新保留当前标签页的访问凭据；重启服务后须使用新链接。

此版本明确面向**单个本机用户**。不同会话共享该用户记忆；`session_id` 是来源标识，不能当作多用户权限隔离。网页服务与 CLI 可以共用 SQLite；纠错或删除后，其他连接下一次读取短期上下文时会清空旧窗口。不要将管理服务转发到公网。

## 记忆反馈与时间衰减

“召回不相关”只增加该条当前记忆的 `bad_hits`，降低后续召回排名。它不代表事实错误，不修改事实、不自动作废，也不替代删除。错误事实请使用“纠正”；隐私删除请使用“彻底删除”。纠正会生成新版本，新版本反馈归零。

普通记忆的时间保留值为 `2 ** (-年龄天数 / 30)`，身份、偏好与明确规则免时间衰减。衰减只调整已经通过关键词/语义筛选的候选排名，不自动删除任何记忆。查看或模型召回不会增强稳定度，避免自我强化。

对话结果的 `recalled_ids` 是本轮召回候选，不保证模型实际使用了每一条。页面按编号反馈，避免由模型猜测反馈对象。

## 提醒

目前只接受明确指令，例如：

- `提醒我明天下午3点答辩`
- `请提醒我后天早上8点半交作业`
- `提醒我下周一上午9点开会`
- `提醒我2027年2月1日晚上8点打电话`
- `取消提醒编号12`

日期、时间、事项缺一不可。支持数字钟点、分钟和“半”，采用北京时间（UTC+8）和秒时间戳；未指定上午/下午的数字按 24 小时制解释。拒绝过去时间、无效日期及一条指令中的多个日期。不做多轮补全，不自动从普通闲聊、引用或假设中提取提醒。

提醒独立存储在 SQLite，可完成、取消或删除。页面打开且服务运行时每 15 秒检查；CLI 在新一轮对话时检查。没有系统后台任务、系统通知或 QQ 推送。界面的“已标记到期，显示未确认”只表示后端认领记录，不能证明页面已显示或用户已看到；当前“已看到”按钮仅关闭本页提示，不回写确认。领取采用事务，多个连接不会重复领取同一条提醒；属于“至多一次领取”，若领取后页面断线，可能未被用户看到，仍可在列表查看。超过 24 小时的旧事项不自动弹出，但列表保留。

联网 MCP 工具只提供提醒查询，不暴露创建/取消写操作给模型。文本对话的创建和带编号取消由 Avatar 对当前用户原文进行确定性解析；网页和 CLI 管理入口也是明确的本机操作。

CLI 增加：`/badhit 编号`、`/reminders`、`/cancel 编号`、`/complete 编号`、`/delete-reminder 编号`。现有 `/memories`、`/memory`、`/correct`、`/forget`、`/reindex` 保留。

## 情绪与活跃度

角色活跃度独立于用户情绪，每次观测小幅上升，空闲六小时后相对中性值的偏差减半。它只为闲聊表达提供弱提示，不会降低任务响应概率，不用“菜”等关键词推断角色心情。网页进程运行期间保留，重启回到中性值，尚不做跨重启人格状态持久化。角色情绪状态默认半衰期为 300 秒；可用 `EmotionEngine(half_life_seconds=...)` 调整。显式传入旧参数 `decay=` 时按每秒保留比例计算，以兼容既有调用。

增加 `close` 策略；明确“晚安、我先下了”等告别要求简短收尾、不追问。翻译或引用“晚安”不应结束对话。模型回复仍需依赖所选模型遵循提示；规则回退提供固定收尾。

## 长对话摘要

超过短期窗口（默认 20 条消息，即约 10 轮）后，系统从更早的用户消息中选择关键原话，优先保留方案、预算、约束、主题和顺序等讨论线索。默认最多 8 条，JSON 内容最多 1600 字符，每条摘录最多 180 字符，最近 200 条溢出用户消息参与筛选。此版本是可解释的摘录摘要，不是模型自由改写的故事摘要，不增加模型调用。

SQLite 摘要表只存消息编号，显示时读原文并重新检查有效性。助手输出、假设、引用、问题、当前身份和偏好来源、已失效事实来源不会进入摘要。检查较保守，包含这类内容的整条消息可能被排除，无法保证所有重要线索都保留。摘要限定当前 session；同一 session ID 重开可读取已存摘要，新 session 不自动继承另一会话摘要，长期用户画像仍跨会话共享。

网页“会话摘要与来源”显示原话、编号与时间，可点“删除此原话”彻底清除源消息及其关联记忆。CLI `/summary` 查看，`/forget-summary 消息编号` 删除。这里使用的是消息编号，与长期记忆编号不同。

纠正或删除长期记忆时，同一事务清空旧摘要选择；重建会过滤已失效来源。提示词明确区分历史讨论线索与当前事实，最终生成仍可能不遵循提示，需通过真实对话评测验证。不要把摘要当作已核实事实写回用户画像。

固定脚本评测：

```powershell
python scripts/evaluate_long_dialogue.py --summary-mode on --models hhu-qwen3-4b-instruct-2507:q4_k_m qwen2.5:7b --output-dir ./eval-results --temp-root ./eval-temp
```

模型须已安装在本机 Ollama。每模型 40 个用户回合，临时数据库独立于真实数据；逐轮保存回复、实际提示词、模型调用、源代码哈希和时延。`--summary-mode off` 可在相同代码上关闭摘要做对照。关键词检查只是窄范围自动评分，不代表整体对话准确率。

## 向量阈值校准

在本机 Ollama 已安装 BGE-M3 后运行：

```powershell
python -m avatar.brain.calibration --pairs scripts/data/memory_pairs.json --model bge-m3 --output calibration-report.json
```

脚本扫描 0.30～0.90，输出 precision、recall、F1 和误召回率，并报告模型身份。不会下载模型或修改配置。附带 16 对样例仅用于冒烟，其中包含他人信息、历史状态等难负例；语义相似度本身无法处理所有主体和时态区别。正式调参应增加真实标注，并使用独立留出集验证混合召回与最终回答。不能将小肥鱼的阈值直接用于 BGE-M3。
