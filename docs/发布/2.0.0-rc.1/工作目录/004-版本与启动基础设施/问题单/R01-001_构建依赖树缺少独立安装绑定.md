# R01-001 构建依赖树缺少独立安装绑定

P2，发布基础设施修复性发现，当前OPEN。首个候选通过了299源码输入、5项UI字节入包和独立wheel安装；但构建器目前只锁定六项Python构建工具版本，前端使用迁移后的已安装node_modules。只绑定package-lock不等于逐字证明实际依赖树与lock一致。

本轮实际Node v22.14.0，npm ls --omit=dev观察见../frontend-tree-observation-v1.json（含原始路径/SHA及实际问题计数）。输出将大量已安装条目标为extraneous；不能把这些条目直接当运行依赖数量，也不能未调查就归因于软链接或说所有包错误。当前候选页面/安装实测仍有效，缺口在构建依赖身份和干净重现。

修复目标：最终候选使用集中数据目录内独立新前端安装/构建根，从已提交lock完整安装并核验实际依赖/工具链身份，记录源、Node/npm、lock与资源SHA；重复构建比较UI字节，确保不依赖散落或未登记包。打包实际依赖的随附声明需保留来源；旧node_modules和所有旧构建/失败原样归档，不删除或覆盖。完整门控在新源/新构建上重跑，不能以本轮观察否认已通过的限定安装证据，也不能提前声称构建完全可重现。
