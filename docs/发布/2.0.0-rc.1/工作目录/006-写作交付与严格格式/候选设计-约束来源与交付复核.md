# 候选设计：约束来源与交付复核

状态：实现前设计，尚未获CPU/原生质量门控批准。依据仅为发布v1 K04/N08/N09与C15/C16/C30已见失败，采用既有来源控制与有界复核继续收敛；旧C28人工原子计划路线维持拒绝。

## 来源与持久控制

复用ResponseFrames已核验的root/cursor/revision，单独metadata行保留当前有效署名、句数、仅正文等约束的来源ID，保存ID与版本/游标，不复制私有正文或整段历史。新根重置旧约束，明确续改保留未解除字段；中间新增约束即使退出20消息窗口也应保持。约束解析只认引用/代码外当前指令；署名文本是写作数据，不授予用户身份或动作权限。

读取时验证根、控制源真实user/非红删/同版本/合法ID次序，并把所有实际读取ID加入回复隐私依赖。隐私失效/缺源/坏版本/游标超前/来源积压不能猜回约束；并发旧完成不得回滚新控制。旧库没有约束状态时不能伪造已恢复完整要求。控制应与唯一当前user来源在同一入场事务提交，取消/遗忘仍沿原不可变turn屏障。

## 交付目标与有限复核

- 署名按来源保留在稿末，不因为画像姓名覆盖【姓名】，也不把它自动当收件人。
- 当前明确句数/仅正文约束分别解析，引用中的约束文本不当操作；停止写作/换题/新任务后不套旧条件。
- 现实请假稿未给理由/日期应保留可填占位或适当澄清，不虚构健康/日期事实；小说/用户已给台词的创作内容仍按有效来源保留。
- 写作任务交付稿件，不能以你是否需要我写代替。有限检查只负责可证明的字面/格式和明确失配，不能冒充一般语义验证器；自然度/充分性仍逐轮非人工source/span审阅。

## 有界修正与显示

先使用有来源字段的写作提示；必要时仅一次有限修正，沿现有SDK取消/来源屏障，不把当前失败草稿当成新的事实或示范。修正未过要保留未满足状态，不冒称合格。强约束稿件完整复核前缓冲，普通无合同聊天保留早出；框架处理/修正分别标生成模式，最终/可见/SQL一致。

## 必需验证

实际SQLite长续改/重开/中间约束/根和控制源遗忘、两个连接竞争/调用方事务、用户角色隔离、SDK/HTTP流/取消/代码引用/原样与解除保护。CPU通过后重新登记固定预算的已知回归及实现后新措辞，逐轮核验实际trace并截断即停。当前18场景与C30原题以后只作已知回归，不改分或重标盲测。没有新的训练或模型搜索。
