# 原生模型通信门控协议 v1

仅验证既有通信能力/发送者来源/代写边界修复，不开启新训练、模型搜索或远期研究。候选当前默认关闭。本协议不覆盖所有身体边界、时间状态或一般心理语义，不能单独批准整体发布。

- 固定现有 Qwen3-4B Q4_K_M GGUF、54个原生运行库身份；先运行完整当前 Python 门控。输入与驱动全部提交后，再以 Git 历史字节和独立 SHA 冻结。加载后核验真实 CUDA 分配、GPU UUID、模型 SHA 和父死亡信号9，拒绝 CPU 替代。
- 启动时按实际余量选一张卡，单 provider 串行；不固定6—7、不停止他人进程。监督器→受保护 worker→受保护 provider 两个明确 exec 边沿用已验证 helper；保留真实 wait 和退出后 GPU 退役记录。
- 材料为 `native-cases-v1.json`：4个已见回归、14个修复后新措辞场景，18场景×两个臂=36试次，每臂31轮，总62轮，最多124次 generate。实际次数以原生 trace 为准，框架只读/拒绝不计模型成功。新措辞不是独立人评或广泛分布代表性证据。
- 每场景先 baseline（当前代码、开关False）再 candidate（仅该开关True），独立SQLite文件/会话；不复用对方文本/缓存为观测来源。既有provider温度0、seed42、thinking=False、上下文8192、每请求最多512 tokens固定，无训练和自动重试；无整轮墙钟截止。就绪180秒、单请求180秒、清理30秒为工程边界，不增加算法重跑。
- 记录认知/生成每次真实输入和输出、原生trace、可见delta、最终结果、实际SQL消息及提醒/回执、来源依赖、每轮实际时间。生成路径合并delta必须与返回reply、SQL assistant一致；固定规则路径允许无delta，以最终结果交付，不能误称未显示，也不伪称流式模型。工具关闭，除明确本地提醒外不得有实际提醒创建；模型拒绝或解析降级必须逐轮披露。
- 工程硬门控：输入冻结保持、所有请求被trace逐一对应且完成、实际GPU身份及进程退出、三层文本一致、实际SQL动作授权一致。工程失败立即停止后续试次并留存已执行结果，不筛选重跑。
- 内容门控另做逐轮来源/span代理审阅：逐条核对用户目标是否交付、谁说谁发、是否虚构能力/动作/送达/ACK、有效代写/引用是否误拦、情绪输入是否处理。禁止把正则零命中或模型自评当内容批准；每条结论保存原文片段与来源，框架改写和模型原生质量分开统计。发现失败必须保留并返工，已运行材料随后只作已知回归，不再冒充未见验证。
- 原始实验放中央数据目录，仓库保存协议、freeze、全量原料SHA、结果和审阅MD/JSON。实验结论不等于真人、物理设备或多日验收；这些仍按用户授权留待下次启动。
