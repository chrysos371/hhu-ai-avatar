# 2.0候选安装与启动

当前为收敛中的候选，尚未完成全部发布门控/创建正式标签。Python版本`2.0.0rc1`与前端`2.0.0-rc.1`表示同一候选。已完成的安装验证见[模块记录](工作目录/004-版本与启动基础设施/范围与门控.md)，后续源码变化仍需重新构建和验收。

## 本服务器源码入口

确认`/data`挂载，在`/data/Users/zrh/repo/hhu-ai-avatar`执行：

```bash
./scripts/avatar --version
./scripts/avatar doctor --require-ui
./scripts/avatar web --port 8765
```

打开终端显示的完整本机链接（含临时鉴权片段）。服务为单用户、仅监听`127.0.0.1`；远程使用时通过SSH端口转发访问。Ctrl+C关闭服务。文本入口是`./scripts/avatar text`；加`--tts`启用文本终端朗读。原`start_web.py`和`python -m avatar.web`继续可用。

源码前端需要构建时执行`./scripts/frontend.sh run build`；本机环境、模型、缓存和运行数据仍在`/data/Users/zrh/data/hhu-ai-avatar`，详见[布局](../../本机数据布局.md)。`doctor`不发网络请求或构造模型，不输出密钥；它只检查依赖、页面资源、数据路径与配置存在性，不能证明已配置服务可达。

## 安装分发包

完整wheel应附前端资源，使用Python3.10以上的独立虚拟环境安装，再执行：

```bash
python -m pip install /绝对路径/hhu_ai_avatar-2.0.0rc1-py3-none-any.whl
hhu-avatar doctor --require-ui
hhu-avatar web --port 8765
```

无需Node或源码目录即可提供打包页面；也可使用`python -m avatar`同名子命令。当前最近已验证候选在本机数据目录`artifacts/release/candidate-build-v4/dist`，源码绑定`59b8a719`，仍不是获批最终分发，也不代表之后源码。该包已在独立环境以459个已安装文件逐字核对、两次鉴权HTTP启动/退出及升级回退通过；[构建证据](工作目录/004-版本与启动基础设施/candidate-build-v4-proof.json)与[安装结果](工作目录/004-版本与启动基础设施/install-smoke-v3-result.json)保留。首个v1及所有中间失败/候选仍在原目录。

## 模型、语音和数据

未设置`LLM_API_KEY`时运行明确的规则模式，不会得到真实模型自由对话能力。通过环境变量或私有`.env`配置`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`；密钥不进入版本库。联网工具和ASR是可选扩展；`hhu-avatar web --help`列出ASR模型/设备参数，ASR默认关闭且不能仅凭安装状态称已加载。没有邮件、短信或电话发送接口。

`HHU_AVATAR_DATA_ROOT`指定环境/缓存/运行资产根，`MEMORY_DB_PATH`可显式指定SQLite路径；本机默认在集中数据目录的`artifacts/memory.db`。不要用安装测试的样本库替换真实用户库。提醒依赖程序与页面保持运行、轮询，只在本机显示；停止程序不会在外部平台自动通知。

## 升级与回退

升级前停止服务，保留旧环境、原wheel及版本/SHA记录；使用SQLite备份API为真实库创建新路径的备份，并记录备份SHA。将新包安装到另一个环境，以备份副本验证迁移与页面/API后再切换启动入口。回退使用原环境和备份恢复出的新数据库路径；保留升级后库与所有失败记录，不直接覆盖原库或删除运行资料。

本次自动门控已用最初`349160c2`源码实际建库，验证两项画像经候选迁移保留，备份不变且原代码能读取恢复副本；这只证明该已登记schema样本，不覆盖任意未来或损坏数据库。真实用户升级应保留自己的备份。

## 构建和批准边界

在集中数据目录的独立构建环境安装`requirements-build.txt`，输入先提交，然后运行：

```bash
构建环境/bin/python -B scripts/build_release_candidate.py --output /数据目录内/全新候选目录
```

发布构建还需要`frontend/build-toolchain.json`指定的Node v22.14.0/npm10.9.2；已安装wheel运行不需要Node。构建器在Git归档frontend内全新`npm ci`，核验完整依赖树、实际工具链与安装文件字节，构建前后保持，避免借用旧node_modules。前端原始许可/notice随包位于`avatar/third_party/`，index列出过包含的实际安装依赖与各原始文本；当前v4的52项完整runtime依赖均核对原文本，开发包无独立文本时据实列出。

构建器拒绝脏源码、遗漏新执行文件、缺失UI、构建工具版本不符或覆盖旧输出；wheel/sdist逐字核对UI和第三方声明，并写入源码/资源/实际依赖身份。输出明确标记`candidate_not_release_approved`，不会自行创建标签或证明整体目标达成。正式发布还需目标/问题台账与最终完整测试门控；[真人/物理/多日待办](下次启动待办.md)按用户授权延期，不能冒称通过。
