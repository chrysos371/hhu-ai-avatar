# 本地动作回执

对话页的“实际本地操作”支持按需核验本地提醒操作，不从模型回复中推断是否执行。点击“核验本地操作记录”读取当前可见的记录；刷新页面后需重新读取。当前提醒状态请到“提醒”页查看。

本轮实际创建、取消提醒或认领到期提醒时，业务更新和回执在同一个 SQLite 写事务内提交；任一失败都会回滚。回执只存用户来源 ID、会话、隐私版本、动作、提醒 ID 和记录时间，不另存消息原文、提醒标题、姓名或联系人。重复设置同一状态不会生成新的状态转换回执。

停止回复不会撤销此前已经提交的操作。因此，已提交提醒后即使回复取消，仍可查到该动作；在事务检查前已取消或来源失效的请求不会写业务或回执。遗忘推进隐私版本后，旧版本回执不再返回；这不表示原先合法提交的提醒被撤销。空列表只表示当前可见回执为空，无法证明过去从无动作。较早版本和直接使用无聊天来源的 Store 接口不会补造历史回执。

到期认领只代表本地 `notified_at` 标记更新，不能证明通知已送达。本功能没有短信、邮件或拨号执行接口，也不验证通用模型文字的真实性。

鉴权只读接口为 `GET /api/v1/conversation/actions`。支持 `source_message_id`、`revision`、`after_id`（默认 0）、`limit`（默认 100，1–200），每个参数最多一次。按回执 ID 递增分页；`has_more` 为真时用 `next_after_id` 继续。指定的隐私版本过时返回 409；参数无效返回 422。服务返回 `instance_id`、当前 `revision`、`items`、分页信息、`scope=current_visible_local_sql_receipts` 和 `notification_delivery_verified=false`。前端核对服务与版本，版本改变、鉴权失败或读取异常时清空旧面板，不自动重放操作。

单条记录字段为 `id`、`source_message_id`、`session_id`、`context_revision`、`action`、`reminder_id`、`recorded_at`。动作可为 `reminder.created`、`reminder.cancelled`、`reminder.completed`、`reminder.claimed_due`。`recorded_at` 是事务内记录时间，不是外部通知送达时间。SDK 成功结果的 `action_receipts` 是该用户来源的同结构分页；更多记录可通过只读接口继续查询。
