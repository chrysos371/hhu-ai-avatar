# 数字人任务技能 v1

这是本项目数字人大脑的任务技能，不是宿主编码助手的Codex技能或插件。角色负责表达和身份，技能提供任务方法，模型负责理解与生成，现有工具系统负责执行。

## 已实现

- 学习辅导 study-coach：讲解概念、例子、出题与答案反馈；资料不足不假装读过课件。
- 文案改稿 writing-editor：直接交付、发送者视角、保留事实与时间、遵守最新格式，不声称已发送。
- 当前每轮最多一个技能。基于当前用户原话进行规则路由，屏蔽引号内容中的触发词。匹配有限，不是通用意图理解。
- 明确改稿/追问可以在最近三条用户消息范围内续接；遇到换话题、倾诉或告别停止续接。没有持久化技能会话状态。
- 只在回复组装阶段注入SKILL.md，不注入认知分析/事实抽取，不把范例写入记忆。examples.json和checks.json仅为设计材料，当前不在运行时自动加载；checks中的文字描述不是可执行断言。
- 技能提示在角色/事实/安全及来源状态组装后，使用剩余预算；最多1800字符，不切断现有安全提示。缺失、无效、路径异常或超预算则跳过并记审计，不中断正常回复。
- 技能只允许context.read能力；不执行脚本、不加载任意路径、不安装依赖、不因技能清单增加任何工具权限。原系统已授权工具仍依原有规则运行，技能不是新的授权来源。
- trace.skills记录enabled、selected的id/version/sha256、reason、错误类型、注入字符数和granted_tools=[]。安全规则直接回应时selected为空，防止沿用上一轮技能日志。
- 公共Avatar、角色馆和QQ的ConversationService路径均接入；工具查询支路不加载技能。未修改QQ登录、发送或正式角色配置。

## 文件

src/avatar/skills/packs/<id>/manifest.json、SKILL.md、examples.json、checks.json。

manifest包含id、name、version与capabilities。内容变更后应更新版本并回归；内容哈希也会变化。项目wheel已验证包含两套共8个技能素材文件。

默认只接受注册在src/avatar/skills/__init__.py中PACK_IDS里的本地技能。新增技能需要项目维护者新增目录、注册ID、选择路由，并补测试。不支持把网上不明SKILL直接自动下载执行。

## 开关与试用

默认AVATAR_SKILLS_ENABLED=0，现有线上服务、正式角色和QQ未被重启或改成开启状态。软件默认关闭，因为小样本未证明稳定净收益。

受控服务可设置AVATAR_SKILLS_ENABLED=1后启动；部署前应完成自己的验收，不能仅因技能文件存在就认为回答变好。应用内构造Avatar、ConversationService或CharacterLibrary时也可传skills_enabled=True/False做隔离对照。

开启加载层后自动识别任务；显式用户输入 `/skill study-coach ...` 或 `/skill writing-editor ...` 也可以选择技能，`/skill off ...`仅关闭当前轮。服务器全局关闭时这些前缀不会绕过关闭状态；本轮选择不等于执行任何脚本。

可以不改正式服务，直接在项目根目录用隔离目录试用：

```python
from avatar.characters.library import CharacterLibrary
lib = CharacterLibrary('data/skills-preview', skills_enabled=True)
result = lib.chat('xiaofeiyu', '帮我解释数字电路里的与门，简短点。')
print(result['reply'])
print(result['trace']['skills'])
```

该目录独立保存试用会话；仍使用已配置的模型，范例没有写到QQ。

## 接入巡检

定时开发套件已加入skill-study、skill-writing两个场景，目前总共8个固定开发场景。每批/每日预算保持原样。现有timer默认沿用全局关闭状态，因此新增场景首先是无技能基线检查，并不自动开启技能。

隔离运行开启/关闭测试，分别指定不同root，避免预算或记忆混用：

```bash
/data/Users/zyyh/envs/hhu-ai-avatar/bin/python -m avatar.lab.improvement run --root data/improvement-skills-on --skills on
/data/Users/zyyh/envs/hhu-ai-avatar/bin/python -m avatar.lab.improvement run --root data/improvement-skills-off --skills off
```

此命令轮换挑选开发场景，不保证每批恰好挑到相同场景；严格A/B必须锁定同一场景和生成条件。本次专门对照脚本和证据见下文。不要把两个不同批次的汇总直接当作增益证明。

## 后台接口

GET /api/v1/skills：沿用既有token鉴权，列出技能ID、版本、哈希、能力与全局开关。无POST编辑、执行接口；不会暴露SKILL全文或任何凭据。现有“最近一轮处理记录”可直接展示新增skills字段，不另建角色配置系统。

## 2026-11-11验证

- 全量Python730通过、4跳过。包含路由、引用屏蔽、换话题、追问续接、预算、无效技能、路径/符号链接、能力升级拒绝、分析与回复隔离、安全trace重置、角色馆通路及HTTP鉴权。
- 第一轮7个场景×每组14轮，共28轮真实本地qwen3-4b-qq；每组12轮模型、2轮安全规则。随后修补追问路由，最终源码对学习来源2轮、连续改稿3轮再跑开启组，共5轮。实际新跑33轮，不是最终源码把两组33轮一次全重跑。
- 六个非安全场景首轮分析输入及参数相同，回复生成参数和用户消息相同，开启组system仅追加技能块；普通聊天未命中技能时system亦相同。多轮模型输出与抽取状态允许自然分化。所有语义结论由同一AI完整审阅，开发材料已见且主题相近，不是独立盲测或用户人审。
- 与门、欧姆定律计算、JSON和改稿在两组均可完成；开启后部分说明更啰嗦，出题有多余铺垫。两组来源追问都没有编造课件；原路由没对该追问和“改到”加载技能，最终5轮复测已确认加载。
- 换话题后技能退出，安全规则优先，所有模型/工具记录可区分。普通聊天的回复变化在selected=[]时不能算技能收益；采样本身也会造成差异。
- 首轮模型路径中位关闭7.758秒、开启8.2855秒；共享CPU服务、未固定随机种子，不能据此建立精确性能结论，但不支持宣称提速。
- 结论：技能框架可用，暂未证明稳定质量净收益，默认关闭；没有训练、部署或QQ外发。
