# Mission Control 本机管理后台

2026-11-10：React 管理台替代原单页记忆工作台。九个页面分别管理总览、对话、人设、情绪、记忆、知识、提醒、工具与审计。它是单用户本机工具，不提供公网、多用户或权限分级部署。

## 启动

在 `/data/Users/zyyh/hhu-ai-avatar` 执行：

```bash
./scripts/frontend.sh ci                 # 首次安装依赖
./scripts/frontend.sh run build
/data/Users/zyyh/envs/hhu-ai-avatar/bin/python start_web.py
```

打开终端打印的完整 `http://127.0.0.1:8765/#...` 链接。令牌进入当前标签页的 sessionStorage 后，从地址栏移除；刷新继续有效。服务重启会换令牌，需重新打开新链接。不要把完整链接发给别人。缺失或损坏构建文件时，页面会显示构建指引。

脚本优先使用本工作区 `runtime/` 下的 Node 22.14/npm 10，也可使用已安装的 Node 22.12+。依赖缓存和临时文件落在 `/data/Users/zyyh/`。网络环境的 DNS 兼容 hook 仅在本工作区存在时供安装命令使用，不进入应用。其他机器正常使用 `npm --prefix frontend ci` 和 `npm --prefix frontend run build`。

开发前端时保持默认 8765 后端运行，另开终端执行 `./scripts/frontend.sh run dev`，在 `http://127.0.0.1:5173/#令牌` 使用同一启动令牌。Vite 仅监听本机并代理 `/api` 到 8765；代理只转换来自本机 5173 的 Origin，其他来源仍被后端拒绝。正常使用优先选择上面的单服务生产构建入口。

后端始终绑定 127.0.0.1，检查精确 Host/Origin 和随机请求令牌；静态资源受路径检查、CSP、no-store 约束。远程使用可通过自己已有的 SSH 转发访问本机端口，不能把服务改成公网监听。数据库默认沿用 `.env` 中 MEMORY_DB_PATH。

## 如何修改

1. 在对应页面编辑；也可用顶栏“管理指令”描述需求。
2. 生成草案，检查逐字段旧值/新值、警告与到期时间。
3. 点击“确认执行”；不可撤销删除还需勾选明确知悉。
4. 后台再次校验基线，原子写入业务数据与成功审计。审计失败则业务回滚。

取消和关闭对话框不会执行业务变更。草案有效期十分钟，一次性确认令牌只存哈希；重复、交叉或过期确认被拒绝。状态变化后旧草案返回冲突，需重新生成。审计中的可逆操作生成反向草案，再次确认后生效；删除不是可逆操作。

人设保存不可变版本，历史恢复也创建新版本。人设影响表达，不能移除内置安全规则。试聊预览只测试本地模型的表达，不激活、不记忆，也不是正式能力或安全评测。

管理模型默认是本机 Ollama 的 `qwen3:4b`，可通过 `AVATAR_ADMIN_LOCAL_MODEL` 指定已经安装的模型。不可用时显示错误，手动表单继续可用。仅勾选“仅本次请求明确使用已配置的云端模型”才会调用 `.env` 中的对话提供方；每次请求后选择重置，不会自动云端回退。管理模型只能提出四种受限操作，不能执行 SQL、任意文件访问或自行确认。

情绪干预仅创建有时限的表达覆盖，自动 PAD 状态、用户情绪观测不受覆盖污染；到期跟随自动状态。安全回应优先。页面趋势只显示本次进程真实对话观测，重启后趋势清空。

记忆支持搜索、类型/日期/来源过滤、原话与历史查看、纠错、不相关反馈和批量删除；个人记忆服务仍是唯一写入入口。来源标志仅代表存在原话或人工纠错，不能当作语义正确率。删除会清理关联版本、原话及管理草案中的缓存；记忆审计保留编号与内容哈希，不复制私人原文。这里的删除是应用层删除，不保证磁盘或备份的取证擦除。

## 知识、提醒与观测

知识只接收 UTF-8 `.txt`/`.md` 或粘贴文本，单文件最多 5 MiB。先查看切片与去重结果，再确认导入。不会按文档指令执行操作。数据存入独立 knowledge 表，不变成用户画像。已确认知识在对话中以不可信资料引用，来源片段可展开查看。

精确哈希与词面去重始终可用；配置 EMBEDDING_MODEL 时使用既有 Ollama 向量提供方，失败回退词面。每次导入最多向量处理 32 段、比较 5,000 个已有向量；更大文本仍按词面处理。**确认执行固定使用已预览的切片**，向量服务状态变化不会偷偷改变导入内容。检索为有限候选的词面/向量融合，不承诺全库语义去重或问答准确率。

提醒须包含明确日期、钟点和事项，以北京时间解释；手工创建、完成、取消、删除都要确认。提醒页面打开且服务运行时每十秒领取到期提醒，只在本页提示，没有手机通知或外部推送。已确认的计划到期领取属于既有调度流程，无需每次重新确认；至多一次领取，断线时可在列表查阅。CLI 与对话中仍保留原提醒行为。

总览计数来自 SQLite，工具页显示实际探测或“未探测”。对话 trace 只列安全路由、召回来源、决策与工具状态，不暴露隐藏提示词、思维链、密钥或向量。未接独立通用语义验证器，因此验收率显示不可用；字面交付检查不是通用语义验收。管理台上线不代表模型质量已提升。

## 数据、备份与兼容

首次版本接口访问自动进行幂等迁移，人设配置只在第一次迁移时作为初始种子。迁移保留原记忆、摘要与提醒表。版本、覆盖、知识、草案和审计与它们共享同一个 SQLite 数据库和事务。

备份时先停止服务及其他数据库写入程序，再复制 MEMORY_DB_PATH 指向的数据库到 `/data/Users/zyyh/backups/`，保留日期。不要在服务仍写入时仅复制数据库主文件（可能存在 WAL）。恢复前同样停止所有写入，再用备份替换指定数据库；不要将运行库、备份、令牌或 `.env` 提交 Git。

正式 `python start_web.py` / `python -m avatar.web` 禁用旧 `/api/*` POST 写接口，返回 410，保留旧只读接口。库函数 `create_server(..., legacy_writes=True)` 默认兼容原调用方和迁移测试；仅供原集成迁移使用，会允许旧直写行为，不能当成确认机制的正式入口。新版 UI 仅调用 `/api/v1/*`。原 `web_ui.py` 保留作迁移参考，不再作为页面回退。

过期草案在后续 API 访问时清空业务载荷；服务关闭或完全空闲期间，过期数据可能留在数据库直到下次访问，但已无法确认。
