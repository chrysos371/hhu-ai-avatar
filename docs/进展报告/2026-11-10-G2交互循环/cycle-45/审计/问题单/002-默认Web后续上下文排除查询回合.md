# C45-002 默认Web与常驻SDK后续查询上下文不一致

优先级P2｜开放，已实测，下一循环处理

[SDK实际采证](../工作目录/001-真实入口调查/sdk-mode-evidence.json)：查询后普通聊天的实际1分析/1生成messages包含查询答复及合成标题。[HTTP实际采证](../工作目录/003-真实HTTP与上下文/v2/http-evidence.json)：默认recover_context=true，10查询都保存为20条真实消息/10可信历史结果，但后续普通Web1分析/1生成不含查询标题。界面刷新仍完整显示查询记录。这不是零模型本轮失败，而是后续模型上下文不一致。

源码依据：ConversationContextStore._result允许的生成模式不含rules_reminder_query，read从最新成对记录往前读，遇到不允许回合就停止，因此不能因页面可见断言后续普通模型已接收该历史。不要把常驻SDK结论推广到默认Web。

优化目标：下一循环先登记统一的数据范围，选择有界、来源/说话者/revision/依赖均验证的新专用查询回合继承或显式隔离策略；保留旧显式查询兼容，明确历史观测不能冒当前状态。用真实HTTP后续模型messages和跨页遗忘/重启/污染元数据控制验收，修改前保留本轮真实原件。本轮不静默扩大历史白名单，不据自动实验称通用语义通过。
