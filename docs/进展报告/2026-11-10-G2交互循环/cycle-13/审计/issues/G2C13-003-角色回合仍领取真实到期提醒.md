# G2C13-003 角色回合仍领取真实到期提醒

P1，已复现，修复后待完整复测。此项并非重启丢失状态，而是已有角色路径的隐藏操作。

main.respond原仅检查安全路由便调用claim_due，角色及未核验归属也可能领取真实提醒，设置notified_at并把提醒加入回复。新测试先进入角色，再创建一个刚到期的真实提醒，继续剧情应不领取；修前在due_reminders==[]断言失败，实际返回该真实提醒。见实验/due-claim-before-valid.log。

首版夹具错用due_at=1，落在既有24小时过期过滤之外，最终真人对照收不到提醒，因此该初始失败不是上述漏洞证据；due-claim-before.log保留。改为time.time()-1后才有效复现。修复增加allows_actions门槛，明确现实确认后另一个独立真人回合仍能领取一次，过期策略不改。

此修复仅针对对话内领取/显示；提醒模块的显式管理/轮询接口仍沿用鉴权契约，不把它描述为外部通知服务或实际设备验收。
