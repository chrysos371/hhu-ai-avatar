# C29阶段B：有界、可溯源的已完成对话接续

阶段A31项证据已封，源按descriptor.source_ref核历史Git，数据不回写。实测重启第三生成缺4条历史角色消息（SQL/API仍有6条），目标为普通网页对话连续性，不是全部记忆或通用语义批准。

## 恢复机制

新增纯读ConversationContextStore，复用memory_messages与当前revision的memory_chat_results，不迁移数据库。Web默认链路在当前user来源与说话者观察的同一写事务内，按current_source_id之前的持久记录构建窗口；旧内存cache不再当默认来源权威。直接Avatar/CLI未安装该hook，实验性identity/profile/task/literal开关保留原路径，不能冒称已验证这些候选的新恢复。

只接受按时间连续的已完成user/assistant对：角色、正文、session、稳定ID、tracked上下文、result.reply、result.conversation引用与当前隐私revision都必须匹配；元数据严格JSON，未知/损坏/旧版本/孤立未完成源/外部写入空隙处截断，不跳过坏源复活更老对话。只恢复当前已核验scope，规范角色切换确认本身可入窗口但作为边界，不能跨切换带回另一角色原文。unverified不装载模型历史。

窗口最多保留short_term_limit-2条并按完整对截断（默认18条），为当前user/assistant留空间；模型消息以user开始、稳定来源无重复。恢复仅复制role/content，绝不重新respond、重新分析旧回合或调用提醒/工具；当前回合正常分析一次仍按既有来源校验。

每次回复必须把实际恢复窗口的所有user/assistant稳定ID加入memory_response_context依赖，即使来自旧session。否则遗忘旧来源后新回复可能漏删，这项与恢复本身同优先级。沿用现有隐私revision检查、递归删除依赖和取消屏障；不引入无来源的持久模型摘要。无需把内部IDs/实现细节塞进产品普通对话。

## 必要验收

| 控制 | 门槛 |
|---|---|
| 原阶段A两协议重跑 | 新源6回合/3OS，前4角色消息同进程/重启均各1，SQL/API与SDK来源一致 |
| 隐私revision/删除 | 旧版本/已删除/改写来源不进入prompt；新revision之后合法新对可恢复 |
| 跨session新回复依赖 | 实际SQL图含恢复源ID；遗忘旧来源会递归红删新回复/移除result，不把已显示当当前证据 |
| 角色/规范切换 | 当前scope已核验，窗口不跨另一scope或规范控制边界；无旧提醒重放、角色输入不变成真人资料 |
| 取消/孤立尾源 | 未完成user/assistant不恢复，空隙处失败关闭；后续合法新对可形成新窗口 |
| 损坏/伪引用metadata | 重复JSON键、错ID/session/role/reply/revision、服务回退等不能装载；不让API500 |
| 未跟踪写入方 | 保持现有unverified与权限确认规则，历史加载不得越权 |
| 窗口/重复/多次重启 | 默认18历史上限、完整对、每源一次、连续SDK角色；固定长序列而非墙钟跑分 |
| 旧副作用 | 恢复/空闲/普通新问题不增加旧提醒/工具执行；独立新真实请求仍按当前权限正常工作 |
| 事务与并发 | SQLite快照/写意图保护装载；隐私变化在当前调用前后仍按既有屏障失效，无旧源提示继续 |

## 决策边界

默认网页可接续其自身可核验完成的最近对话；旧库/CLI或未知来源不会凭可见文字自动成为模型历史。未完成/跨角色/隐私版本会截断，属于保守范围，不宣称无界跨进程语义。C19-001及自然任务质量继续开放。实现、失败和测试按步骤spinner-bot提交/推送，最终系统MD/HTML之后再封全轮。
