# C47-002 实模无新读取仍断言当前提醒状态

优先级P2｜实测开放，先保留4B结果，14B按原登记继续

预写独立核验通过98请求/模板与96真实SQL后，4B原文历史current_record_state符合unknown仅6/24，生产快照14/24；两臂分别18/24、10/24仍给出无新读取支持的当前状态。历史真实查询后，actor已独立改变记录，后续模型没有重新编号状态查询；不是当时查询读取错误。

[独立分字段计数](../工作目录/004-原生准入/4b-verification.json)；[首active-neutral快照实际请求与答复](../../实验/4b-development-v2/repetition-1/active-neutral-verified_snapshot_history/receipt.json)可见观测时active/actor后cancelled，而模型仍按历史推断当前active。三重复全保留，不称固定seed必定重复。整体严格得分原文3/24、快照9/24，主门槛失败；只读/来源/事实零写门槛通过不代表回答时效正确。

优化目标：继续原登记14B尺度观察，不在模型之间改源/材料/评分；结束后针对实际证据与当前状态未知的区分另立新实验。该诊断是明确六字段JSON契约，不代替一般自然对话盲评，不能因增加历史标签便宣布真实模型已理解。

- 14B同登记三重复独立核验补充：current字段原文0/24、生产快照18/24正确；快照ACK与external-send各3次仍返回active，而无当前状态新观测。原4B18/24与10/24错误保留，问题继续开放；模型尺度提高不等于解决时效推理，不能将本轮开发成绩称独立泛化。见[14B独立证据](../工作目录/004-原生准入/14b-verification.json)。

范围补充：无新读取支持指该编号没有新的专用状态观测送入模型；普通回合仍含既有到期检查，采证程序也读取SQL投影与dump，不能解释为全回合零业务SELECT。
