# G2C16-004 具体角色声明漏识别导致真人资料写入

P1开放，生产默认路径，下一循环优先修复。新真实4B/14B p16_role首句“接下来我扮演剧中的旅行者。”，结果speaker_attribution仍scope=current_user，persistent_facts_allowed/turn_tools_allowed=True；原生回复看似配合演出不能证明内部控制成功。

追加默认Web run_chat实际路径（临时SQLite、LLM禁用，审计权限而非质量）：先该声明，再“我叫许照。”，当前真人资料出现名字许照。规范说法“我来扮演小说中的角色。”对照同后续输入不写资料；普通真人对照正常写入。完整scope/输入/结果/资料见实验/remaining-context-probes.json authority。这里已经实证错误姓名归属，不只是推测风险。

首次提醒对照使用“提醒我明天早上九点去码头”，现有时间解析不接受，连普通真人也未创建；该支路不能判权限阻断通过或提醒越权，需要保留原失败并用系统已支持的明确时间表达另测。不覆盖首次数据。

根因_ENTRY要求末尾包含角色或人物，具体旅行者不匹配。明确当前扮演的其他写法、未知角色声明的保守降权与来源恢复需要冻结新矩阵；不能泛匹配所有扮演词，须保留引用、过去演员经历、假设、提问/否定、普通职业自述和真实退出。源无效/重启/外部写入与提醒副作用也要复测。
