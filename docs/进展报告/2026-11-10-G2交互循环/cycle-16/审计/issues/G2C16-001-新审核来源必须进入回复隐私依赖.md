# G2C16-001 新审核来源必须进入回复隐私依赖

P1候选发布阻断，尚未启用生产。设计v2读取20消息窗口以外写作根时发现：现有final_reply_reviewer虽能返回元数据，但核心不会把新来源ID合并入助手响应的memory_response_context。新审核若据此保留或改写回复，会引入隐私依赖漏项。

两项实际SDK受控红测试均失败：传入真实旧会话user来源ID的reviewer元数据后，助手响应未绑定该message；随后基于该来源创建记忆再遗忘，来源被redact，但该新助手响应仍未redact。见实验/review-source-before.log与tests/test_review_source_dependencies.py。夹具回复无真实隐私，不能夸大为已泄露用户数据或生产默认路径退化。

修复目标：仅对已安装的可信进程内reviewer，接受至多4个实际存在、未redact、非未来的user来源ID，在原助手写入事务的依赖集合中合并；无效元数据拒绝发布/写助手。原取消/revision屏障不弱化，默认无审核器不增加这类依赖或开关。v2安装前先修此扩展契约并复测原删除失败。

修复已将校验后的来源合并至原助手提交的依赖集合；原两个失败转通过，9种无效ID/容器拒绝发布并不写助手。相关结果见实验/review-source-after.log。候选及完整系统验收尚待后续集成/回归，不能由此启用v2。
