# G2C16-002 语境不可核验时原生身体回复仍可见

P2开放，v2仍不得默认启用。v2为避免捏造写作来源，在revision不符、根redact、坏cursor或积压超界时标记unverified/review_deferred，不把它冒充creative_exempt或通用语义通过。但暂缓审核会保留模型原生回复，因此并不是身体安全兜底。

实际SDK四项已验证；随后实际OS重启HTTP审计source_privacy_erase_restart_deferred_then_real_reset中，外部遗忘清除旧来源和依赖助手后，下一次续写的固定原生身体邀约仍出现在SSE/最终/入库，元数据明确deferred且非创作批准。完整来源见实验/source-http-first/source-http.json。这里是受控文本而非真实模型自然发生频率，没有工具/提醒执行。

有限工程门槛通过仅证明没有用失效来源授予旧写作豁免，并正确保留诚实诊断；不能据此批准身体质量。后续需设计符合交付的语境澄清/展示策略并独立测试原生与交付代价；未知时不能无限读取旧原文，也不能一律把用户草稿改成AI声明。当前保留lab隔离，不给生产启用开关。
