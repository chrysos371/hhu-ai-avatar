# 结构化回复设计审查与本轮决策

依据：原固定8输入4B/14B诊断共20原生调用，8个schema臂全通过；自由邮件草稿两模型/两臂仍给老师补出提交义务，受约束草稿都含字面反斜杠n。用户未明确提交主体，因此是忠实性风险，不能把老师行为强断为已证实错误。状态词题是用户要求输出已发送，不能单凭plain照写计真实执行谎报。逐字任务4B plain额外句号、schema精确；14B两臂均精确，只是一个有界例子。

## 候选所需结构

1. 对外动作状态来自当时能力与事务回执，模型不能自报执行；该状态可由schema固定并确定性呈现，但须标明是框架控制。
2. 草稿主体、受众、义务、事实和时间需要明确来源引用。原文未指定主体时保留未指定，不能因为收件人是老师便给老师分配任务。单纯draft:string没有这个保证。
3. 用户保护原文复用既有compose_literal_plan和来源slot，不重复造一个只换外壳的实现；新增的应是内容原子来源/版本契约。
4. 将事实句约束到来源原子、只允许非事实礼貌片段的有限编辑计划，是可实验方向，但可能损失自然表达和任务覆盖。没有覆盖/拒答/语义数据前不合入默认产品，也不以模板将模型问题从计分中藏掉。
5. 模型原生JSON、框架呈现、真实动作回执、SSE/最终/入库分开采证。现有plain-only关联器不能直接使用；C25修复后的wire/schema身份是必要前提，仍不是请求用途分类器或内容语义验证器。

## 决策

本轮不实现“只包JSON外壳”语义候选，不启用新默认，不关闭C19-001。阶段B仅完成设计审查，未进行应用候选或新前瞻实验；原C23 v4仍拒绝。这是数据驱动的设计否决，不是格式失败，也不宣告代际跃迁。
