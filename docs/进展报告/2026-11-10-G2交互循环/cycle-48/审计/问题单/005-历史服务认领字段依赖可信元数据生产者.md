# C48-005 历史服务认领字段依赖可信元数据生产者

优先级P3｜候选生产接入前的来源契约硬化开放；不是已证实的公共接口漏洞

两模型退役后，追加明确后验纯函数故障注入。使用已采actual query/SQL，原record服务认领false；只把调用者传入metadata.state.service_claim_recorded改为true，原公开回复及源绑定不变，生产历史包装相同，类型化候选却把该true加入观测结构。该标志并未叙述在公开回复中，有限字段类型与原文一致性校验不能独立认证它。另改ACK/status/title三项因与原回复不符而不增加投影，是实际反对照。

[追加探针原件](../工作目录/005-历史元数据一致性/metadata-probe.json) / [已提交脚本](../probe_metadata_consistency.py)。0新SDK/0native/0新SQL dump，只重建1份既有SQL；真实模型采样时该字段全部与真实SQL一致，原生输入/成绩未改。探针直接向纯helper传入人工损坏字典，没有证明用户能通过公开SDK/HTTP修改该元数据，也没有真实未授权认领。

优化目标：在实际产品接入前明确可信生产者/恢复缓存边界，或省去当前八字段任务不需要、且不能由公开回复独立绑定的认领字段；不要把类型正确直接称完整来源真实性。下一版应保留故障注入负控，同时维持原SDK/Web来源/版本/隐私校验。当前实验候选继续隔离，不回写冻结源码或旧分。
