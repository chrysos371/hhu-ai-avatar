# G2C18-002 失效排队发送及旧结束回调影响新回合

P2，接显式语境按钮前发现的客户端异步归属缺口。实际ChatPage与TanStack MutationCache的受控异步onMutate延迟、fetch/SSE夹具下两项均失败：隐私epoch已失效但排队mutationFn尚未开始，释放后仍POST旧文本；另在新回合已经运行时，旧排队任务结束会reset当前MutationObserver，丢失新回合等待/停止界面。

原始复现见tests/test_ChatQueuedPrivacy对应前端文件及实验/queued-privacy-before.log。是受控排队配置，不是当前默认App自然发生频率，更没有据此证明真实数据库副作用或真人隐私泄露。现有最终结果epoch屏障能丢弃旧显示，但不能替代发送前检查和当前请求归属。

目标：发送前核验epoch/挂载/同步；在调用mutate之前同步记录当前提交ID，隐私取消未开始排队时释放该归属；结束时只有归属同一请求才能reset当前观察器或状态，旧结束不能冲掉新任务。按钮切换仍独立控制消息，快速连点也不能生成两个任务。保持取消/草稿/隐私已有回归，不放宽原断言。
