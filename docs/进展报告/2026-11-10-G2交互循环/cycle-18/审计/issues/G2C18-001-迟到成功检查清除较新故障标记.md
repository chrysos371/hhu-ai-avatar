# G2C18-001 迟到成功检查清除较新故障标记

P2，共享版本监测既有实现的受控并发缺口。扩充context通知前按已冻结协议先测顺序：较早check读取成功但暂停返回，另一个check已报告SQLite故障；较早成功随后publish会无条件清_error。两项顺序对照1失败/1通过，见实验/check-order-before.log与test_conversation_check_order.py。

已实证错误缓存可用状态被清除；尚未测自然发生频率或浏览器旧trace可见帧，不能把状态单测冒称已泄露内容。API和共享监测可能并行check，不能仅按启动序号判读结果新旧，因为较早启动的读取也可能较晚才失败。

目标：每次读取记下开始时的故障世代；只要期间观察过故障，之前在途成功不能清除它。任何实际读失败继续标不可用，必须故障之后启动的成功读取才恢复。保留revision单调、旧2字段响应、容量/断连/闲时和API提交核验规则；再做原顺序、恢复及现有HTTP回归。
