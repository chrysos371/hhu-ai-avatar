# C35 接口与方案研究

C34未改前端功能。当前EmotionPage 10秒轮询，DashboardPage 15秒轮询；后者尚需本轮实际before验证。已有watchConversationChanges只传instance_id/revision可读隐私版本，不必加载历史；附带context_cursor是Chat的可选能力，自动状态页面不需要。

候选实现：情绪与概览响应加入与自动状态同一次快照绑定的context（实例+隐私版本），不泄露文本。前端两页复用版本查询hook，初次用不可能等于32位十六进制实例的state-bootstrap游标取得即时元数据；随后最多一个路由等待连接。版本变化/不可用先屏蔽派生值并取消旧查询，查询键绑定实例/版本/本地epoch，拒迟到或错版本返回。复用同/跨窗口隐私通知触发重核，普通消息不清合法情绪。现有Chat独立hook不做大范围重构。

人工override独立，表单分别标记valence/arousal是否真正编辑；未编辑自动预填遇隐私变化清除再填新状态，已编辑值保留。所有这些是待实现/待实验证实的设计，不是已完成结论。

保持C34后端源在本轮两页before完成前不改；每阶段代码与实际bundle分别先提交归档后冻结，匹配固定3重复。新原生/GPU调用不必要。C34历史proof的current=True只代表当时，后续改源后须按Git历史复核，旧seal不回写。
