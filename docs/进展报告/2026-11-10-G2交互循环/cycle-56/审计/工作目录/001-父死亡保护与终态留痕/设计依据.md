# 父死亡保护设计依据（2026-11-20查阅）

Linux父死亡信号只覆盖调用进程的直接父线程，普通exec保留，fork子代不继承；设置之前父已终止不会补发，因此必须核对父身份并关闭竞态。身份/凭据或带权限exec也可能清除保护，不能泛化成整树托管或断电恢复。依据[Linux man-pages：PR_SET_PDEATHSIG](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)。

Python文档明确多线程中preexec_fn可能在exec前死锁，优先在独立新解释器安装内核保护后exec可信payload；必须等exec后身份或可信握手，不能把保护器过渡argv错误当最终工作进程。依据[Python 3.11 subprocess文档](https://docs.python.org/3.11/library/subprocess.html)。

本轮拟用不可忽略SIGKILL保护直接worker，正常显式停止仍经监督器转发SIGINT；硬杀监督器时资源退役与可恢复wait退出码是两件事，原status须保持未知。以上是机制约束和设计推论，具体实现验收以本机真实CPU故障实验为准，不冒称GPU或主机断电已验证。
