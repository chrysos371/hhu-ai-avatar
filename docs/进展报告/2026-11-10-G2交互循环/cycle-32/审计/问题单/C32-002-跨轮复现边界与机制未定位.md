# C32-002 跨轮复现边界与机制未定位

优先级P2；C31-003继续开放，本文件为后续调查记录，不增加一个重复优化项。

## 现状与实验结果

C31三重复材料题中，32B当前分析路径回复93，隔离候选回复37 + 46 = 83；两臂最终SDK原字节及native prompt SHA相同。C32从C31封存数据提取共同前四请求、有/无额外认知两链，原字节重放，预登记三策略与反向模型策略顺序，每模型105调用。

本轮32B reuse三重复均无额外认知回复算式83、有额外认知回复93，复现了C31的该定性模式；4B各策略六个最终回复均算式83。32B logical_reset与memory_clear_reset各六个最终回复全部93，两链相同。这证明在本轮同GPU条件下策略与前序关联的观察存在，不代表已经识别具体后端机制。

## 已控制与未控制的边界

- 本轮同模型三策略在相同实际GPU5 UUID执行；每次重测余量，单提供方串行。两个模型均40441MiB/0%启动，实际分配4096/21042MiB。C31原4B GPU6、32B GPU4不同，不能宣称跨轮硬件完全相同。
- 本轮54包/所选运行库文件完整SHA前后核验；两个Python源文件与官方v0.3.19完整Git blob相符。C31没有完整二进制指纹，不能反向证明其安装与本轮完全相同。
- 每模型18末次请求的原始SDK与native prompt SHA相同；模型GGUF/revision、采样参数、schema/grammar与三重复顺序已核验。只是逻辑计数、实际显式调用和记录源码得到绑定，未捕获完整GPU状态、每步logit或所有内核中间量。
- reuse不是绝不reset，库内部仍可能重置；安装0.3.19的显式reset只归零逻辑token计数。底层clear在自建context调用，不承诺所有物理状态相同；不能套用latest文档的新reset语义。

## 审计结论与优化目标

“最终请求字节相同且temperature0”不足以保证本次后端在不同前序下回复相同。预登记重置干预在本题改变了32B两链差异，但并未提高正确性，不构成默认启用理由；不能据此直接认定KV缓存、随机数或浮点实现就是根因。

保留C31原质量门槛False与所有旧原文；不追改旧结论，不用新实验替换旧失败。下一次若深入后端归因，应另行冻结明确变量（例如计算批次或每步token/logit观测）并保持提示不变，验证观测工具本身是否改变行为。没有这些数据前，严格使用“已知题定性模式复现、机制未定位”，继续隔离候选。项目当前优先补真实隐含情绪影响，避免仅围绕单道材料题无限调优。
