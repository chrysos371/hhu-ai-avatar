# 实现与资料核对（未运行策略实验）

本机llama-cpp-python版本0.3.19。已记录54个包Python/原生库及明确选取的CUDA运行库文件SHA（约4.31GB），不是整个操作系统或所有GPU状态的身份保证。llama.py与_internals.py本机完整文件的Git blob SHA分别与官方v0.3.19文件完全匹配。引用依据为[固定tag主实现](https://github.com/abetlen/llama-cpp-python/blob/v0.3.19/llama_cpp/llama.py)和[固定tag内部上下文实现](https://github.com/abetlen/llama-cpp-python/blob/v0.3.19/llama_cpp/_internals.py)。

该固定版本的reset只把逻辑token计数设为0，底层上下文另有memory clear方法。最新API页的reset已多出_requires_eval及特定模型类型分支，不能反向套用于本机0.3.19；见[官方API页](https://llama-cpp-python.readthedocs.io/en/latest/api-reference/#llama_cpp.Llama.reset)。本轮不升级环境，私有底层方法只在明确固定版本的研究提供方中使用。

这只是源码/版本观察，不证明C31差异一定由KV缓存或数值精度造成。三个策略需实际调用/trace、逻辑计数前后值与相同wire实验验证；底层clear调用成功也不自动证明一般确定性。C31只有包版本而没有本轮新增的库二进制指纹，不能反向保证旧C31所有后端二进制与现在逐字相同；本轮策略比较会各自前后核验。
