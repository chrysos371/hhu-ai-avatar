# 网页语音与最小形象

更新：2026-11-11。Mission Control 对话页现有流式回合、生成取消、可选自动分段语音、麦克风打断、播放时钟口型、SVG 最小形象和可选本机语音输入。

## 启动

```bash
python -m pip install -e '.[audio,web]'
./scripts/frontend.sh ci
./scripts/frontend.sh run build
python start_web.py --port 8765
```

前端需要 Node.js 22.12+；Python 需要 3.10+。本工作站隔离环境位于 `/data/Users/zrh/repo/envs/hhu-ai-avatar`，可用其中 `bin/python` 替代命令中的 `python`。其他机器沿用各自虚拟环境。

打开启动终端提供的完整链接，在“对话观测”发送文字，点击回复旁的“朗读回复”。Edge-TTS 会将所选文字发送至在线语音服务；默认不自动生成或播放语音；勾选“自动朗读”后只对最终审核回复分段合成，最多预取下一段，生成草稿不先朗读。播放器支持暂停、拖动进度和重播，“停止播放”会释放当前音频；再次朗读会重新生成。

端口占用时使用 `--port 8766`，或使用 `--port 0` 自动分配空闲端口。`GET /healthz` 可检查本机进程是否响应；它不代表模型、网络、数据库或 ASR 已通过质量验收。管理 API 继续要求启动令牌，服务仅绑定 127.0.0.1。

## 可选本机识别

默认不开启 ASR。先安装可选依赖，并准备与 FunASR 兼容的本机模型目录：

```bash
python -m pip install -e '.[asr]'
python start_web.py --asr-model /absolute/path/to/local/paraformer-model
```

Web 入口指定模型目录、使用 CPU、关闭自动更新。FunASR 本机模型的兼容性仍需单独验证。也可显式启用已验证的 faster-whisper：

```bash
python -m pip install -e '.[asr-whisper,audio,web]'
python start_web.py --asr-backend faster-whisper --asr-model /absolute/path/to/faster-whisper-small --asr-device cpu
# 单张有余量的 GPU；启动前实际检查 nvidia-smi，N 是当次选择
CUDA_VISIBLE_DEVICES=N python start_web.py --asr-backend faster-whisper --asr-model /absolute/path/to/faster-whisper-small --asr-device cuda
```

只读已有本地权重，CPU int8、CUDA int8_float16；CUDA 需匹配的 CTranslate2/cuBLAS/cuDNN 运行库。当前实测模型 revision、权重哈希和 27 条固定合成开发语料结果见 G2 阶段报告；第二轮另固定 40 条公开 AISHELL-1 朗读人声，CPU/GPU CER 7.23%/6.88%；小样本不能代表自由对话或物理麦克风准确率。

开启后可点击“麦克风输入”，授权浏览器麦克风；默认手动点击“结束并识别”。可以显式勾选“停顿后自动结束录音”，开启后在检测到语音后停顿约 1.2 秒自动结束并识别，8 秒未检测到足够音量则释放麦克风且不转写；也可上传 PCM WAV 文件。最长 60 秒、最大 6 MiB、16 位、8–48 kHz、单/双声道。浏览器录音用 AudioWorklet 生成单声道 48 kHz PCM WAV，限于支持 AudioWorklet/getUserMedia 的浏览器安全上下文（本机 localhost/127.0.0.1 或 HTTPS）。

自动端点尚未通过真人文件无损门槛：40 条对照中出现提前截断，完整/自动 CER 为 6.53%/9.88%，因此默认关闭。详见 G2C2-012。该端点为固定能量规则（RMS 0.006、连续 240ms），高噪声可能误激活、轻声可能漏检；此时可关闭自动结束。原始起音保留，未提前裁切。

转写结果追加到消息草稿，检查后点击发送；上传和转写本身不写对话或记忆。取消和离开页面会释放麦克风并忽略迟到响应。识别默认仅调用本机注入引擎，不调用云端 ASR。

## 时间轴与资源规则

- 情绪决策的语速、音调、口型强度随回复返回，朗读沿用该组参数。
- 合成后解码 PCM，通过原有 LPC 共振峰分析生成 `time / mouth_open / vowel / energy`。
- 浏览器每帧按 `audio.currentTime` 二分取口型；暂停、结束、停止与离开页面时闭嘴。表情由 PAD valence/arousal 映射，待机动画可随系统减少动态效果设置关闭。
- 每次朗读最多 2000 字、8 MiB、解码后 120 秒。生成并发上限 1；Edge-TTS 网络合成超时 30 秒。音频缓存最多 8 条/32 MiB，15 分钟过期，进程重启清空；过期在下一次缓存访问时清理。
- 临时文件随处理结束清理；浏览器通过令牌头获取二进制音频，再创建 Blob URL。令牌不进入音频 URL，API 不返回本机路径。音频属于运行数据，不提交 Git。
- 取消朗读使用 request_id 取消服务端异步 Edge-TTS 任务并释放队列、预取与 Blob URL；生成回合取消会关闭本机 SDK 异步任务与连接。不能据此断言第三方计算/计费已停止；同步工具和 ASR 推理可能只在阶段边界退出。
- 解码或分析失败时保留可播放音频并提示口型不可用；TTS 故障保留文字并允许重试。

## API

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/speech` | `{text, request_id?, rate?, pitch?, mouth_intensity?}` → 音频 ID、过期时间、时长、口型帧与降级提示 |
| `GET /api/v1/speech/audio/{audio_id}` | 带 `X-Avatar-Token` 读取 `audio/mpeg` 或 `audio/wav`，`no-store` |
| `GET /api/v1/speech/capabilities` | 查询 ASR 是否启用与上传限制 |
| `POST /api/v1/speech/transcribe` | `Content-Type: audio/wav` 原始字节 → `{transcript}` |
| `POST /api/v1/speech/cancel` | `{request_id}` 取消该次合成 |
| `POST /api/v1/turns` | `{request_id, text, use_web?}` → 202 回合；同 ID 去重 |
| `GET /api/v1/turns/{id}` | 查询回合 |
| `GET /api/v1/turns/{id}/events?after=N` | 令牌头鉴权 SSE，重放后续事件；非法/超前游标 422 |
| `POST /api/v1/turns/{id}/cancel` | `{}` 取消生成 |
| `GET /healthz` | 受本机 Host/Origin 限制的进程响应检查，无敏感配置 |

回合任务最多 32 条，15 分钟后在访问/提交时清理；请求账本持久去重，结果已过期或进程重启后拒绝重跑旧 ID。已接受的用户消息可能保留，取消中的助手半成品不写历史。删除记忆会使相关任务/事件/音频缓存失效，并按来源链清理持久化助手派生文本；旧无来源助手消息保守脱敏。

JSON API 沿用 `{data, error, request_id}`；音频读取直接返回二进制，错误仍返回 JSON。

## 有界资料候选与真实模型检查（2026-11-11）

已验证本机4B/14B真实链路，未自动更换默认模型。CLI可显式加 `--identity-grounding` 开启身份来源提示、加 `--profile-grounding` 验证当前资料查询与保守声明确认；两者默认关闭，且不自动互相开启。资料候选只有窄范围保证，不是通用语义Verifier。当前4B追加逐轮门槛仍失败，不据52项最终检查通过就启用。

结果中的 `generation_mode` 区分 `llm`、`profile_lookup`、`profile_grounded` 与规则/故障回退；`profile_grounding` 记录版本、适用范围、动作和是否整段缓冲。确定性资料回复仍可能调用原有情绪/事实分析，不代表完全没有模型调用。为了避免检查前文字流出，开启资料候选时模型文字须整段检查后发送，六对固定知识题的首个可见中位0.889→1.115s，存在可见延迟代价。

声明确认保留普通任务、情绪/关系扩展、创作、翻译与假设的原路径，默认不作为全面自由对话方案。完整[系统审计与证据](进展报告/2026-11-10-G2交互循环/cycle-02/审计/系统审计与推进报告.md)包含已修复样本、仍开放的边界、原始失败和真实浏览器结果。

## 原文保护文案实验入口（2026-11-11）

已配置兼容模型后，可显式运行：

```bash
python start_web.py --task-delivery-check --literal-composition
```

两项均默认关闭，后一项必须同时开启前一项，并要求模型支持JSON schema。普通对话入口不自动开启身份/资料候选或切换模型。

任务检查识别成对引号原文、【占位符】的保留/禁止与明确改稿。跨网页回合只从当前隐私有效的短期窗口内用户原话恢复任务；不重放模型、工具或提醒，窗口之外的旧任务不推断。明确的新问题、寒暄或话题切换会释放旧约束。写提醒文字与实际“提醒我...”动作分别处理。

仅在首稿不满足已识别约束时允许一次修正。模板v2只使用用户任务来源和明确作者/收件人，不把失败初稿、画像猜测或无关助手历史交给规划器；框架将保护标记单次替换为原文。`generation_mode=llm_literal_composition` 表示框架参与组合，`delivery_check.repair_mode=literal_template` 表示实际使用模板；不能当作原生模型质量分。检查/修正期间先缓冲，在发送和后续模型请求前核对取消及来源版本。

实验支持最多8条固定原文、8条禁止原文，引号内容最长120字符，【】内容最长40字符；模板任务来源最多1200字符、最终正文最多4000字符。未支持的复杂表达不保证被识别；修正失败会保留原稿并记录 `repair_error`、`remaining_issues`，不会静默追加原文追认成功。它验证的是已识别的字面约束，事实、自然度、情绪与自由对话身体边界仍需独立检查，通用语义Verifier继续未配置。

第一版多槽位方案虽36/36字面通过，但出现重复/断句及编造时间地点，未放行；新版仍是实验功能。全部正反例、旧失败与本轮结果见 [第三轮进展](进展报告/2026-11-10-G2交互循环/cycle-03/进展.md)。

## 显式角色与真人操作范围（2026-11-11）

用户明确说“我来扮演小说角色”后，后续角色姓名、偏好和事件不会写成真人事实，网页跨回合保持范围。说“回到现实”或“退出角色”可恢复；如需真实提醒/联网工具，请退出后单独提出请求，角色台词和切换同回合不会执行真实操作。原先真实提醒的到期通知仍正常。对小说的喜好和请助手写故事不等于用户在扮演角色。

这是有限显式语法，不保证所有自然语言角色转换都识别；新运行会话需重新声明，历史污染需按记忆来源检查纠正。对话原文仍保留为消息，阻止事实写入不是删除原文。实证见[第四轮审计](进展报告/2026-11-10-G2交互循环/cycle-04/审计/系统审计与推进报告.md)。

## 口型分析边界（2026-11-11）

默认由声源能量/静音驱动，不再每0.3秒插入装饰闭口。组件LipSyncEngine可显式设置close_every正数恢复装饰，默认None；它不是发音停顿检测。直接调用需归一化有限单声道PCM、整数采样率及可表示的窗口/跳步，非法数据明确拒绝，预取消在分帧前传播。

解析合成基准证实移除突降且保留帧时间/标签/能量，不能推为真人自然度或中文元音准确率提升；现有LPC漏峰/采样率敏感、ü及声调仍未完成。见[第五轮报告](进展报告/2026-11-10-G2交互循环/cycle-05/审计/系统审计与推进报告.md)。

## 等输出分析缓存与实验候选（2026-11-11）

默认仅缓存频率几何，最多8项只读数组；不会缓存用户音频、LPC系数或口型结果。固定CPU基准分析阶段中位加速约2.49倍，已知路线输出四字段相同，不代表模型/TTS/页面整体加速。提峰修订未通过新参数试验，留在avatar.lab.ConservativeLipSyncExperiment，不作为生产选项，网页默认没有接入。详见[第六轮报告](进展报告/2026-11-10-G2交互循环/cycle-06/审计/系统审计与推进报告.md)。

## 样本时钟与显式装饰事件（2026-11-11）

口型time表示实际分帧起点，现按整数样本跳步/sr计算。22050Hz等不整除名义hop的输入不会再累计漂移；整数hop和默认开口/元音/能量保持。组件显式close_every改为各绝对目标分别映射最近帧，事件相位误差至多半hop，极小周期最多一次/帧；默认仍None。这些是软件元数据与装饰调度检查，物理播放延迟和真人嘴型仍需独立验收。见[第七轮报告](进展报告/2026-11-10-G2交互循环/cycle-07/审计/系统审计与推进报告.md)。

## 媒体事件与重复播放研究（2026-11-11）

播放器核对所拥有的blob源和currentSrc，按当前paused/ended/error处理回调，迟到事件不能复活已停止播放或消费当前片段队列。实际PCM/DOM研究覆盖变速、拖动、暂停/结束与三段顺序；双速初次p95超门槛和后续同机重复通过均保留，延迟根因仍待研究。这些控制层数据不代替真实语音/音素和物理设备验收。见[第八轮报告](进展报告/2026-11-10-G2交互循环/cycle-08/审计/系统审计与推进报告.md)。
