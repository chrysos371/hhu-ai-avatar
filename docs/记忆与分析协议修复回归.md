# 记忆校验与分析协议修复回归

本轮完成两类确定性漏写修复与分析输出协议约束，并用同一份真实Qwen3-4B量化权重、同一组20条对话回归。目标检查全部通过；这不代表关系边界和危险情绪回应问题已解决。

## 修改

- `brain/facts.py`：允许“现在/目前”等时间词位于明确自述主语前，正确处理“现在我不喜欢喝咖啡了”；同句连续的“也/还 + 偏好谓词”可继承明确当前自述的主语，保留完整句子作为后续并列事实的证据。对象仍分别校验、分别更新。
- 继续拦截假设、引用、问句、过去状态和其他人的谓词；未知话题会打断主语继承，多对象歧义不会自动猜测反转对象。新增不同水果、食物和活动的测试，避免只匹配原评测词汇。
- 新增`brain/analysis_protocol.py`，统一定义严格emotion/facts JSON Schema；`LLMEngine.chat_analysis`和评测适配器使用同一schema。普通回复不加JSON格式约束，事实的主体、极性和原文证据仍单独验证。
- `Avatar`优先使用专用分析接口，只有chat方法的旧自定义引擎继续兼容。损坏内容不通过猜测修复入库；服务不支持json_schema或解析失败时，现有规则回退继续可见。支持范围见[后端说明](backend.md)。

没有修改行为策略或添加新的现实边界规则，也没有训练模型。

## 自动测试

先用复现测试观察到5个预期失败：两种时间词前置表达和三种并列表达。修复后原有安全守卫、历史更新、证据校验等相关测试通过。最终全量pytest结果为 **379 passed**，含MCP/Web测试。

新增测试还验证：普通聊天不带分析schema，Avatar分别调用分析和回复接口，偏好反转后旧值成为历史而当前值正确，并列偏好不会互相覆盖。

## 剩余问题

抽查关键场景仍能看到共同散步经历编造、过度承诺及危险情绪下现实支持不足；咖啡首轮仍编造自身饮用经验。memory-13虽然数据库正确存入两项，语言末轮的歧义澄清仍不充分。这些不属于本轮已修复范围，也未重新给20条做完整语言质量评分。

后续应在独立开发场景上处理现实边界、危险情绪支持和策略遵循，再构建SFT/DPO数据。分析格式可靠只解决协议问题，不意味着情绪数值和事实候选在语义上都正确。
