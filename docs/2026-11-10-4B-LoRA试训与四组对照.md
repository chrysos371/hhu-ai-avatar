# 4B LoRA 短程试训与四组开发对照

结论：工程链路完成，尚未证明 LoRA 质量增益；抽查有任务交付回归，本轮不部署。数据未人工审核，语义质量仍为 unscored。

## 训练与重载

- 底模：固定 revision 的 Qwen3-4B 原始 BF16 权重，非 GGUF；仅物理 GPU 0。
- 可用训练池200条，开发50条。本轮12个优化步、每步累计4条，实际训练48条样本。
- LoRA r=8、alpha=16、q_proj/v_proj、学习率2e-5、seed=42；只监督最后助手回复，提示与历史不计损失。
- 可训练参数 2,949,120；训练阶段（含末尾开发损失与探针）28.75 秒，未包含加载与后续评测；PyTorch峰值 8.16 GiB，不是整卡占用。
- 训练后开发损失 7.9283，没有相同条件的训练前 NLL 对照，不能据此推断质量收益。
- 独立Python进程重载通过：logits最大差异0，探针生成逐字一致。
- 权重、数据、配置及tokenizer哈希均记录；适配器已保存，未覆盖原底模。

## 具体抽查（AI审阅，非人工批准）

- lora-dev-01：用户要求改写成客观问题描述。后台原版给出客观改写；LoRA组转为解释原句并推断不满，没有直接完成改写。
- lora-dev-02：同样风格提示下，两组都给出“待处理”“需跟进”；LoRA组额外添加解释和“需要我帮你进一步调整吗？”，属于窄任务上的额外追问。
- lora-dev-03：LoRA组保留了甲的两项表态，但用户要求一句话，它拆成两句；提示组是一句。后台原版同时还存在遗漏一项表态的问题。不能把某组包装成全面正确。
- LoRA整体平均回复长度与提示组接近，含问号轮数26对28；不能从局部例子推断整体更啰嗦。这些具体交付回归没有被现有机械检查捕获。

## 完整性与限制

- 390次模型调用中有165次分析调用，分析阶段适配器泄漏为0；240轮均有回复，无分析/回复回退；裸模型3轮被截断，分布于2个场景。
- 训练和评测记录的源码差异仅为实验CLI与runner新增裸模型入口，训练器和Avatar后台文件哈希相同。四组对照在同一评测进程、同一后台源码下运行。
- 20条为已暴露开发集，不是独立盲测；自动筛选回复不是角色视角/任务交付专项重写数据。12步仅验证小规模适配，不代表充分收敛。
- 这里评测标准Avatar后台，不含QQ协议、联网工具实际调用、14角色长期一致性或量化部署回归。
- 没有启用DPO/OPD，没有自动扩大训练，没有更换QQ或角色馆权重。本次GPU占用已释放。
- 结束健康检查发现QQ登录已失效，客户端日志提示需要重新登录；本地模型服务正常。本轮未尝试重新登录或发送QQ消息。
