# 后端记忆、情绪与检索

## 偏好校验与分析协议修复

明确自述支持时间词位于主语前（如“目前我不喜欢辣椒了”），以及同句连续并列谓词（如“我喜欢看书，也喜欢画画”）。并列部分继承主语只限未被其他话题打断的明确当前自述；假设、引用、问句、过去状态和其他人的谓词仍不继承。每条事实保留用户原文连续证据，历史版本与当前状态继续分离。

标准LLM适配器增加`chat_analysis`，使用`response_format.type=json_schema`请求严格的emotion/facts结构。普通聊天不使用此约束，事实内容仍经过原文证据验证，结构正确不代表事实可信。服务必须支持该格式；若拒绝请求，现有回退机制继续可见地退回规则，不自动重试无限次，也不对损坏JSON猜测补写。旧的自定义适配器若仅有`chat`仍兼容原有分析入口，但不具备服务端格式保证。

评测适配器采用同一份schema，并在每次调用记录response_format；分析解析失败仍记录fallback_events和degraded，不能因启用约束就默认分析成功。

## 提示组装与隐私版本（2026-11-12）

默认Avatar为每个respond保存独立revision，在回复消息组装前和全部组装后检查同一版本及取消，分析发送前也检查。get_short_term刷新清空短期消息不能清除已编译system中的旧资料，本实例forget/correct更新任务版本也不能授权旧回合。实际独立连接遗忘交错中，修前遗忘后仍1次含旧合成姓名的回复HTTP，修后0次；最终取消/不入库不足以撤回此前请求。最后检查后的新写入及历史/在途提供方请求不具有追溯撤回保证。见[第二十一轮隐私阶段报告](进展报告/2026-11-10-G2交互循环/cycle-21/审计/隐私修复阶段报告.md)。

## SDK、文件与事实事务边界（2026-11-12）

默认SDK在回复提交后、TTS调用前后、解码后和结果返回前复核原始turn及取消token。内置Edge TTS在同目录自有临时文件写入，核验非空及来源后原子替换；失败/取消只清理自己的临时文件，保留既有目标。检查回调在调用线程执行，覆盖合成过程中来源改变。自定义TTS的内部发布策略和已经开始的外部阻塞调用不能据此获得追溯撤回保证。Edge适配器受控save与文件测试不代表本轮实际访问Edge服务或物理发声验收。见[SDK与语音阶段报告及浏览器勘误](进展报告/2026-11-10-G2交互循环/cycle-21/审计/独立SDK与语音修复报告.md)。

LLM与规则事实批次在SQLite写事务开始、逐项写入和批次结束时核验不可变原turn与取消token，避免同实例公共forget/correct改写当前状态后让旧分析结果重新入库。锁等待后的失效及批次尾取消均有真实SQLite反例与回归；这不构成任意自定义重入回调的普遍安全证明。提醒业务与回执亦在同一写事务检查来源，取消发生在合法提交之后时不撤销已提交操作。见[事实事务阶段报告](进展报告/2026-11-10-G2交互循环/cycle-21/审计/认知事实事务来源修复报告.md)。

## 当前处理链路

`用户消息落库 → 有证据的事实抽取与时间解析 → 原子更新当前记忆/历史 → 用户情绪观测 → 角色状态与回应策略 → 当前记忆混合召回 → 回复落库`

事实写入前必须验证主体、语气、时间与原文证据。假设、问句、他人引用不会作为用户画像。明确姓名和偏好有保守规则补全；复杂反讽、转述和省略仍可能漏记，不能把规则当作通用语义理解。

## 偏好更新与历史

- `我喜欢喝咖啡` → `我现在不喜欢咖啡了`：后者为当前值，前者保留为历史。
- `我以前喜欢喝咖啡，现在已经不喜欢了`：同句中解析出明确对象与当前否定。
- `我喜欢喝咖啡` → 下一轮 `我现在不喜欢了`：只在紧邻上一轮有唯一明确对象时解析；若上一轮同时提到咖啡和茶则不猜。
- 不同对象共存，重复事实附加来源。偏好/爱好旧字段可共享同一对象的版本链。
- 当前画像、普通检索和向量检索均排除历史版本。历史需显式查看。

SQLite 迁移是增量、幂等的：不替换已有表和记录ID。首次用新版本打开旧库会增加元数据及来源表。重要旧库可在首次运行前自行备份。

## 查看、纠错、删除

交互式 CLI：

```text
/memories                 查看当前记忆
/memories history         连同历史一起查看
/memory 12                查看编号12的事实、原文证据、会话与时间
/correct 12 不喜欢咖啡    手动纠正；新版本替换旧值
/forget 12                删除整条相关版本链
/reindex                  重建当前事实的向量
```

Python API：

```python
avatar.list_memories(include_history=True)
avatar.inspect_memory(12)
avatar.correct_memory(12, "不喜欢咖啡")
avatar.forget_memory(12)
```

纠错创建新版本，删除会移除关联版本、标签、来源和向量，并清空当前短期上下文，避免旧值再次被提示词使用。包含被删除事实的共享原始消息与引用会整体标记为 `[redacted]`，因此其他事实仍保留，但可能失去该条共享原文。这里是应用层逻辑删除/脱敏，不承诺SQLite文件的取证级物理擦除。

自然语言中的删除请求不会让模型猜测删除目标。使用明确的编号命令或API。命令不调用大模型。

## 用户情绪与角色状态

- `user_state`：最新用户情绪观测，不累加成永久标签。
- `state`：角色自己的状态，按经过的实际时间回归基线；用户愤怒不会直接令角色愤怒。
- `Decision.strategy`：`listen`、`clarify`、`empathize`、`advise`、`celebrate`、`answer`。
- “不想听建议”优先倾听；“帮我分析怎么复习”切到实际建议。策略进入提示词与无模型回退，不仅改变采样温度。

`respond()` 保留 `emotion/valence/arousal/style`，它们表示角色表达；新增 `user_emotion/user_valence/user_arousal/strategy`。旧代码若把 `valence` 当作用户情绪，应改读 `user_valence`。

## 可选语义召回

默认关键词检索仍可离线运行。需要语义召回时安装/启动Ollama，准备本地向量模型：

```powershell
ollama pull bge-m3
$env:EMBEDDING_MODEL="bge-m3"
$env:EMBEDDING_BASE_URL="http://localhost:11434"
$env:EMBEDDING_TIMEOUT="60"
python -m avatar.main
```

也可自行填写 `.env`；项目不会自动改写它。配置为空时不连接向量服务。

- 使用真实模型向量及NumPy余弦相似度，与关键词候选按排名融合。
- 向量存储模型标识和维度，模型/维度变化时按当前模型重建，避免混用向量空间。
- 同名模型权重更新无法仅凭标签发现，请运行 `/reindex`。
- 当前默认最小相似度0.45，同时过滤明显弱于首项的语义邻居。`EMBEDDING_MIN_SIMILARITY` 可调整；阈值是启发式，需要按模型和数据调优。
- 懒加载只索引当前事实；服务失败退回关键词召回。首次加载模型较慢，可先 `/reindex` 预热；失败会保留原索引。
- 模型标识包括服务端点和标签。默认连接本机；若自行配置远程端点，待检索文本会发送到该端点。

不需要Chroma、Postgres或新的强制重依赖；小规模先用SQLite存向量。

## 对话历史快照（第十一轮）

`GET /api/v1/conversation` 使用既有token鉴权，只读当前数据库消息，不重放模型/工具。可传 `limit`（1..200，默认100）、正数 `before_id` 与非负 `revision`；重复/未知/非法参数拒绝。响应含 `instance_id`、`revision`、按来源ID升序的 `items`、`has_more`、`next_before_id`。翻旧页版本已变化返回409 `conversation_changed`。

消息含 `id/role/text/session_id/created_at/redacted`；新的隐私有效助手回合可附原 `result`。旧记录或已失效trace不伪造，已删除正文返回明确占位。新 `ChatResult.conversation` 含用户/助手消息ID、session与revision；原结果在事务内核验来源后保存，记忆失效同时清除旧结果。页面默认100条，可显式加载更早；已载入范围同版本合并不截断。

第十一轮外部API删除后12/12 RAF仍显示旧trace的失败保留；第十二轮新增鉴权 `GET /api/v1/conversation/changes?instance_id=...&revision=N`，旧调用精确返回当前 `instance_id/revision`。第十八轮可选增加一次 `context_cursor=C`，响应仅增加该字段（最新user来源ID，空库0），不含转录/事实/trace。参数必须各一次；非法参数422、等待容量满429、版本读取暂不可用503。已变化立即返回，未变化10秒心跳。每页一个挂起请求；每服务最多4个且保留至少1个普通连接名额，一个共享监测器在有等待者时每100ms检查其他SQLite连接，成功API响应前也检查已提交版本。普通peer断开释放自身等待，不取消其他回合；关闭停止监测。普通来源变化仅更新当前语境，不作为隐私删除清历史或取消已提交回合；故障后的恢复要求新的成功读取，迟到旧成功不能清除已观察故障。

客户端通知失败会暂停旧显示、停止旧播放/生成；焦点和手动刷新不能在版本连接恢复前重新展示。250/500/1000/2000/5000ms上限退避、每请求15秒超时；401/403停止并提示使用启动链接重新打开。同版本重连也重新读取快照，不重放模型/工具。超过4个同时等待的页面可能暂停并重试，不支持无限标签页保证。

原失败探针固定三轮均0/12旧trace可见；新增断网、同版本重连、自然姓名更新、实际播放及生成中删除各通过。此为本机有限受控实验，不是所有网络的零延迟保证。历史显示恢复也不表示服务重启后的生成短期/角色状态自动重建。见[第十二轮系统审计](进展报告/2026-11-10-G2交互循环/cycle-12/审计/系统审计与推进报告.md)。

网页增加“以本人说话”“进入角色”，分别发送独立固定原话“回到现实。”“我来扮演一个虚构角色。”，保留输入框草稿，固定不联网、不自动朗读。当前模式只以来源快照确认；待发/生成/语音占用或隐私同步不可用时停用相应操作。普通消息须先取得当前快照，并携带可选`expected_context:{instance_id,revision,context_cursor}`；三个字段精确，两个数字为非负安全整数。规范模式控制不绑定旧游标。

`POST /api/v1/turns`有该字段时，在用户源同一`BEGIN IMMEDIATE`写事务内核验，失配任务以`error` SSE的`code:speaker_context_changed`结束，不写用户源、短期、事实、提醒，不调用模型/工具。已接收HTTP仍202；最终冲突通过事件读取，不等同POST立即409。客户端先重新核验；同服务器、同隐私版本才恢复待重发草稿，不自动重试。隐私变化/重启/核验失败不恢复旧文本。语境绑定计入幂等标识，重复同请求不重验已因自身提交而增长的游标，改变约束同ID返回409；过期/重启后的历史请求仍410且不重放。旧无字段客户端保持原三字段指纹及处理时全局语境语义，不自动获得新界面约束。
