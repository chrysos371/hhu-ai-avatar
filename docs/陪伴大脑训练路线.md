# 陪伴大脑训练路线

状态：15条试点评分尺度已获用户批准，已扩展100条候选评测；新增场景待审核，尚未冻结正式评测集，尚未训练模型。

## 阶段与交付

| 阶段 | 输入与产出 | 进入下一阶段的条件 |
|---|---|---|
| 评测 | 先审阅15条多轮样例，再扩展约100条正式评测；独立开发集用于调试 | 人工审核评分尺度、场景覆盖和分组隔离，记录版本与SHA256后冻结 |
| 数据 | 约1,000条，云端教师生成候选回复与偏好对，规则校验、去重、人工抽检 | 来源、授权、过滤结果可追踪；训练/验证/评测按场景家族隔离 |
| SFT | 本地4B LoRA，学习陪伴风格、人设稳定、工具边界和记忆引用 | 同协议重复评测有增益，关键边界无回退 |
| DPO | 经审核的chosen/rejected偏好对，校准共情、记忆、现实边界和工具行为 | 相对SFT有稳定增益，报告各类结果与运行波动 |
| OPD | 面向复杂情绪、长期关系、记忆冲突和现实边界的难例迭代 | 先确认OPD具体算法、反馈形式、训练目标、实现及预算；SFT/DPO已达标 |

OPD是后段能力路线的名称占位，当前不将普通离线偏好数据循环宣称为已实现的OPD。教师的“判断过程”应先表达为可核验的决策标签、证据引用、工具选择与简短理由；是否需要token级分布或在线学生采样，取决于后续确定的算法。后台人设、情绪、记忆和知识管理负责可控上下文、人工纠错和审计。

## 第一轮文件

- `evals/companion/pilot.json`：15条原始试点，每类5条；评分尺度已通过，原文件保留审计，不是正式冻结测试集。
- `evals/companion/candidate-100.json`：保留原15条并新增85条，记忆35、情绪35、边界30，共310回合。当前候选包含已公开讨论的试点，正式盲测前须另补未参与调试的保留集；不宣称这100条都是从未见过的独立测试。
- `docs/陪伴评测规范.md`：评分与复现要求。
- `scripts/evaluate_companion.py`：模型直测、Avatar集成和离线冒烟入口；生成JSON记录与待人工评分的CSV。

试点评分尺度已通过。下一步审核100条候选的新增内容，准备独立开发集与未暴露保留集，固定放行标准后冻结正式评测。之后确定4B/7B具体模型、云端教师、预算与部署方式，跑原始模型和Avatar集成基线。不得将试点调试结果写成正式模型效果结论。

训练数据保留scene_family、来源、教师/提示版本、已确认记忆证据、候选回复、偏好对、规则结果和审核记录。正式评测及其改写、派生难例不进入训练；发现泄漏后更换受污染测试并升级版本。1,000条是起步规模，不代表充分覆盖。
