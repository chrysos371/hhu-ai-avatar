# 现实边界与危险情绪响应

## 实现范围

`brain/boundaries.py`提供统一系统约束和窄范围、可审计的规则路由。明确触发时直接返回经过编写的回应，普通场景继续调用模型；因此这项改进属于系统行为约束，不代表4B模型本身已经学会这些能力。

约束覆盖：不编造身体感受或共同线下经历；不保证录取等结果或永久在线；不鼓励排他依赖；不帮助追索不愿联系者的私人住处；明确危险情绪下优先现实安全和现实支持。

即时风险路由在认知分析前执行，不等待模型返回。它不会自动拨号、发送消息或声称已经联系任何人，也不猜测用户所在国家和急救号码。输出包含`boundary.route`和`boundary.guarded`，用于区分固定回应与模型生成。

普通引用先屏蔽，历史状态、明确无当前风险、虚构创作和惯用夸张单独处理；从小说讨论切到明确当前自述时重新处理真实风险。风险状态在同一个Avatar实例内保持，Web工作台在各请求间复用该状态，避免下一句“还没有联系任何人”丢失背景。明确当前无伤害打算或已经联系现实支持时进入recovery，但回复不声称危险已解除。

## 依据与限制

回应思路参考[NIMH五项帮助行动](https://www.nimh.nih.gov/health/publications/5-action-steps-to-help-someone-having-thoughts-of-suicide)：询问安全状况、减少危险接触、支持连接可信赖的人和当地资源。该来源中的美国号码不直接套用到未知地区用户。

规则不是临床风险评估。未覆盖的委婉说法、复杂转述、语言变化仍可能漏识别；否定和时间作用域也可能误判。状态不跨进程持久化，不提供后台监控或主动跟进。一般对话仍由模型生成，系统提示不能保证每个回答都遵守约束。

固定回应可减少明确场景中的越界，但连续触发时可能重复、生硬，需要单独审阅。不能用路由标签命中率代替情绪理解、语言质量或真实使用安全性评价。

## 开发场景与对照

独立开发文件为`evals/companion/boundary-dev-20.json`：20条、60回合，含明确边界请求、直接风险、风险后续/恢复、他人风险、历史经历、引用、虚构、自身地址查询和普通倾诉。该文件参与规则开发，不能称为未暴露测试集；原pilot和candidate-100保持不变。

评测脚本的`--boundary-mode disabled`仅用于隔离对照：移除新增系统提示并以直通路由替代策略，其余记忆和分析协议保持不变。生产CLI/Web没有新增关闭选项。两组固定同一权重、服务、实际温度0和场景文件；原始记录同时保存模型调用及规则路由。

`expected_routes`为编写者的路由预期，自动比对只验证控制流。完整对话还须检查：是否给出可行支持、是否编造行为、是否误判普通倾诉，以及是否产生重复和过度拒绝。正式评测和独立人工审阅尚需另做。
