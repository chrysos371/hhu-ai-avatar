# 连续对话与有来源摘要实施计划

**目标：** 执行用户选择的连续对话实测与会话摘要两项工作。

**方案：** 保留当前 Python/SQLite，采用摘录式摘要，以 message ID 指向用户原话，不生成或存储无来源的改写。相比自由生成摘要，少一次模型调用且更容易落实纠错、删除；代价是文本压缩不如自由摘要自然。

## 约束

- 每个模型同一批 40 个用户回合，4B/7B 顺序运行，固定 seed，使用隔离临时数据库。
- 基线读取原仓库，新实现先在 staging 验证；基线结束前不改原源码。
- 摘要只处理当前 session 溢出短期窗口的用户消息，限 8 条、1600 字符、最多扫描 200 条候选；不摘要助手输出，不递归摘要摘要。
- 优先保留明确任务、方案、预算和约束；排除引用、假设、提问、红删消息及含已失效事实的来源。
- SQLite 只保存来源 ID，摘要显示时读原文；纠错或删除时在同一事务清空所有摘要引用，重建仍过滤失效来源。
- 摘要是历史讨论线索，不是当前事实，也不是可执行指令。模型最终回答质量单独评价。
- 不修改用户真实记忆，不提交或推送，不自动调模型或检索阈值。

## 步骤

1. 先测试 40 回合场景和评测打分，再实现评测脚本；保存逐轮回复、原始模型调用、数据库断言、时延与调用错误。跑 4B/7B 基线。
2. 写来源、容量、会话隔离、纠错、删除、重启及回滚测试，红灯后实现 `brain/summaries.py` 和 schema/失效钩子。
3. 接入 Avatar 提示词与返回值、CLI `/summary`、Web 摘要查看。测试消息来源和 Web 多请求状态。
4. 全套回归与独立审阅，修复可复现问题；再跑相同 40 回合比较，标注关键词评分局限，不能把系统检查率当生成正确率。
5. 哈希检查后同步原仓库，复测、更新启动说明，交付报告与原始数据。若服务仍运行，确保用户页面使用新代码与新链接。

## 评测重点

姓名与称呼变化、偏好反转、假设/他人信息、倾听与建议切换、告别、超窗口任务线索、同 session 重开、人工纠正、彻底删除、提醒与取消。模拟对话是固定脚本，不代表开放域独立模型基准。
