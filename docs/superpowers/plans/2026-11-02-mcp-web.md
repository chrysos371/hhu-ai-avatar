# MCP 联网工具实施计划

目标：实现用户已选择的 web_search 和 read_webpage，接入当前同步 Avatar/Web/CLI，并实测本机4B与7B。

方案：沿用已装 MCP 1.27.2 的 stdio ClientSession/FastMCP，固定可选依赖 mcp>=1.27.2,<2 与 ddgs==9.16.1。MCP v2 有破坏性 API 改名，本轮不混用。单轮工具链共用一个子进程连接，结束后关闭，不把项目整体改为异步。

1. 先测试网络层：公网 URL、所有重定向、证书、字节/时间/正文限制；本机 Clash fake-IP 使用公共DoH解析和固定IP连接，HTTP代理 CONNECT 同样固定公网IP。只允许 HTTP(S)80/443，禁本机/私网/凭据。网页正文跳过脚本、样式、隐藏内容，标明截断。
2. 用 DDGS 自动选择可用搜索入口（最多5条），返回标题、链接、简述；失败明确报错，不把无关 RSS 或验证码当成功。记录来源和获取时间；不自动下载附件或执行页面。实测该版本禁用了部分文档列出的后端，采用 auto 避免假定后端存在。
3. 实现独立 MCP server，两种工具严格校验参数。stdio stdout仅协议、日志stderr。客户端环境只传运行必需项和联网代理，不传LLM密钥或完整.env。
4. LLM 增加独立 chat_tools 接口，保留现有 chat 行为。工具编排最多3次调用、参数白名单、重复检测和时间限制；原生工具选择不支持时，显式 /search 与 /read 仍可执行。规划阶段只给当前用户请求和本轮网页结果，不给个人画像/历史摘要。
5. 网页增加“联网”勾选项、来源链接与调用状态；默认关闭，由用户本轮启用。CLI /search /read。工具结果不进入用户事实抽取；回答来源只来自实际返回的链接。网页数据不作为系统指令。
6. 测试先行验证各层，完整回归、真实stdio握手、真实搜索/读取及两个模型的原生选择与项目端到端体验分开评估。独立审阅修复后哈希同步原仓库、复测并重启页面。

边界：不做登录网站、浏览器点击、付费API或外部写操作；不承诺免费搜索可用性或页面JS渲染。不能绕过验证码，搜索受阻时清楚报告。真实网站测试只发送通用查询，不用用户真实数据库。
