# 小肥鱼机制移植计划

目标：在现有 Python / SQLite 后端上增加可操作的记忆反馈、本机管理页面、未来事件和可解释的活跃度。

沿用用户已接受的渐进移植方案，不迁移 QQ 桥或 JSON 存储。继续在 staging 验证后同步到原仓库，保留所有已有改动，不提交用户数据库。

## 实施与验证

1. 记忆反馈与衰减：迁移增加 bad_hits；显式按 ID 反馈，只改变召回排名，不自动删除。身份和规则免时间衰减；访问不能自动强化；测试重新打开数据库、纠错重置、无关查询、历史列表。
2. 未来事件：独立 SQLite 表，明确提醒指令才写入。中国时区，秒时间戳；支持明天/后天/日期/周几与钟点，拒绝歧义及无效日期。到期领取事务防重复，可取消、完成、删除；不向外部平台发送。测试日期边界、否定、引用、重启与重复领取。
3. 角色活跃度与 close：独立于用户负面情绪，以交互/时间决定表达强度；结束语不追问，任务中出现“晚安”不误收尾。测试时间衰减与主流程返回。
4. 本机管理界面：标准库 HTTPServer 单线程，每个请求创建自己的 SQLite 连接；仅监听 127.0.0.1，随机 token 防跨站写入，严格 Host/Origin、JSON、请求大小限制。页面查看来源/历史、纠错、硬删除、不相关反馈、创建/管理提醒；使用 textContent 显示内容。测试真实 HTTP 与持久化。
5. 检索校准：离线标注数据与向量阈值扫描，使用现有 embedding provider，无默认下载；报告正负样本指标，不照搬小肥鱼阈值。
6. 全套 pytest、CLI/HTTP 冒烟、审阅与同步；仅同步本次列出的源代码、测试、文档。

## 范围边界

本次服务面向一个本机用户，多会话仍共享这个用户的长期记忆；不把 session_id 当作多用户权限边界。多人认证和用户隔离需独立设计，界面与文档明确标注。

## 主要风险

- 衰减不可压过明确相关性：仅在候选集内排序，不扩大候选集。
- 已删除版本链仍需彻底删除，反馈不是删除替代品。
- 提醒不做模糊自动推断，不把假设/他人的计划写成本人提醒。
- Web 管理与对话共用 SQLite，但连接不跨线程共享。
- 不承诺模型生成一定遵循提示，返回可检验的召回 ID 和提醒数据。
