# 后台事实来源、角色状态与草稿引用修复

2026-11-11。回复侧第一版修复已实现，并完成真实14B对照及格式回归修复；没有训练、启用LoRA或重启线上服务。4B基线和已有模型配置保留。本次不是全领域事实正确性或线上质量批准。

## 实现

公共入口新增 `brain/reply_context.py`：从当前窗口用户原话重建发信主体、接收方、表达视角及来源；旧助手回复不成为用户事实。事实纠正与重新起草可以隔离旧助手内容；旧稿编辑与纯格式收尾保留实际草稿，原数据库审计历史不删除。角色馆与QQ的上下文组装经过相同入口。

显式申请询问可直接把用户问题组成正文，不补机构名、材料或审批结果；这是 `grounded_user_inquiry` 规则回复，不能归功于模型或LoRA。其他明确角色任务增加窄范围输出检查，最多一次重生成；仍失败则明确阻止把它当作可靠可发送正文。任务流式候选先缓冲校验，再交付，防止先泄露被拒绝草稿。

`reply_context` 与 `context_check` 进入逐轮结果和统一trace，展示来源数量、隔离/保留条数、角色是否有来源、检查/重生成/失败状态及直出规则来源ID；不额外记录身份值和用户原文。窗口ID不是数据库全局消息ID。管理人设、长期记忆权限、共享范围和外部工具权限没有扩大。

使用说明及限制见 `docs/回复侧事实与角色上下文.md`。

## 验证方法与证据范围

固定整合版、原始Qwen3-14B revision `40c069824f4251a91eefaf281ebe4c544efd3e18`、BF16/SDPA、greedy、seed42、无thinking、分析512/回复256、上下文4096。无LoRA，同GPU0、同STYLE_HINT，唯一实验开关为 `reply_context_enabled=False/True`。每场重建状态、每轮10秒情绪时钟，交替两组运行顺序；工具、网络、TTS和语义嵌入关闭。

先完整跑42场景，每组118轮，共236轮，包括之前36回归及6条生成前固定的独立开发场景。发现纯格式收尾的两处真实退步后，收窄逻辑，再新跑全部7个受影响场景和3条前瞻控制，每组30轮，共60轮。已完成的两轮共296轮新回复；最终证据覆盖45个独特场景、两组合计254轮。

这不是最终源码一次性重跑45场景：另外35个场景依据消息历史、注入提示和直出选择的逐轮字节等价证明复用完整回归数据。源码差异断言确认只有“无角色格式收尾保留草稿”和“无角色编辑不加角色提示”两个收窄改动，7个受影响场景全部重新生成。每场来源见 `origins.json`，等价证明见 `equivalence.json`。前3次中断的开发探索保留在01–03目录，不计入296轮，也不作为完整验收。

重新生成的原100轮无开关基线与上次验收逐字相同，未复用旧缓存充当新实验。AI检查了完整对话及确定性核算；不是独立盲测、人工批准或泛化统计。6条开发及3条追加控制均在各自生成前固定，但同一AI知晓失败家族；格式补丁已使用字段开发场景定位问题，不能再称这条是未见测试。

## 已观察到的改善

| 问题 | 原后台 | 本轮结果 |
| --- | --- | --- |
| 甲/乙说话人纠正 | 中间轮仍猜乙通知，最后遗漏甲通知 | 中间轮承认乙没发言，最后甲拒绝并负责通知、乙未知 |
| 学生社团询问信 | 编已备齐的材料，模型也易站审核方 | 最终直接来自用户问题“您好，请问材料是否齐全？”，不补材料或宣布审批 |
| 姐姐本人回复 | 末轮仍写“我姐姐的卡” | 末轮用本人语境及【房号】，无“之前已提交房号”无据完成状态；两次检查重生成通过 |
| 意见记录员 | 中间稿自行承诺将投票并公布结果 | 中间稿只说收到两建议、未投票未决定，最终保持权限边界 |
| 真正的上稿编辑 | 必须依赖助手实际生成的标题/代号 | 前后缀、保留第二项、转换JSON均保留本组真实上稿，而非丢历史后另编 |

明确区分最终交付和早轮表现：姐姐场景早轮仍有代办/本人视角摇摆，老师给家长场景初轮仍会在主题未给定时编写学生/学校近况。申请询问信的改善来自有来源的确定性组装，不证明14B已经学会所有角色判断。

## 发现并修回的退步

完整42场景中，新布局题从正确882/294退到894/294并加JSON围栏；新字段交换题最后从qty,sku,note退回sku,qty,note。错误并未被机械0失败发现，原结果完整保留。

## 安全、失败与性能

最终对照每组127轮：原后台122轮模型回复+5轮规则；修复后120轮模型回复+2轮来源直出+5轮规则。修复后3次重生成均通过所定义的窄检查，最终无被阻止的正文；这不等于通用语义正确。分析端无适配器，错误、认知/回复降级、截断均0。

危机/匿名关联的5轮仍由相同规则响应，不能计为新模块或模型安全收益。普通倾诉、拒绝排他、现实地址拒绝及合法征同意改写未见新增安全问题；既有过强安慰、随时可用等宽泛措辞并未全部修好。

合并证据的轮耗时中位约2.33→2.32秒，P95约7.15→7.34秒。来自共享服务器和两次运行，不是隔离性能基准，不能声称普遍更快。角色写作可能多一次生成并缓冲流式交付；来源直出则省正文生成。累计共享进程显存峰值27.87GiB，两组未单独重置，不能据相同峰值称零额外成本。GPU0已释放。

## 仍有边界

当前规则基于常用显式中文句型，不是通用人物/事实理解器；复杂、隐式或否定式角色切换可能漏识别，不能把“未检测到问题”理解为事实已验证。无主题写作仍可能编细节、部分许可请求仍有多余追问、早轮代拟视角也可能不稳。没有重构长期事实schema、整合所有真实记忆审计或证明长期陪伴泛化。

下一阶段应基于这些剩余失误扩充独立开发检查，保持用户事实与任务角色分离；不把已暴露评测直接制成训练数据，不按本次LoRA配方扩训，不自动上线。
