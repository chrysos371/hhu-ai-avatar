# 技术选型与模块重写计划

> 项目：基于人工智能的综合性虚拟形象探索与应用（河海大学大创）
> 参考实现：`moeru-ai/airi`（Neuro-sama 复刻，MIT，TypeScript/Web 全栈）

## 1. 项目定位

打造一套让 AI 虚拟形象拥有「过去」（长期记忆）与「心情」（情绪状态）的底层认知框架，
打通 **听 → 思 → 演 → 记** 全链路闭环，形成带记忆、有情感的拟人化交互底座。

本计划的核心策略：**参考 AIRI 的算法与设计思路，用 Python 重新实现，并在其短板处（中文口型、成熟记忆、情绪决策）做出差异化。**

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                     用户（终端 / Web Demo）                 │
└──────────┬──────────────────────────────┬───────────────┘
           │ 语音输入                      │ 语音+口型输出
           ▼                              ▼
   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
   │ 听 ears/    │   │ 思 brain/   │   │ 演 mouth/   │
   │ ASR(FunASR) │──▶│ LLM + 记忆   │──▶│ TTS(Edge)  │
   └─────────────┘   │  + 情绪决策   │   │ face/口型   │
                     └─────────────┘   └─────────────┘
                           ▲
                           │ 读/写
                     ┌─────────────┐
                     │ 记 memory/  │
                     │ SQLite+向量  │
                     └─────────────┘
```

四层模块 + 贯穿全链路的情绪状态：

| 层 | 目录 | 职责 | 选型 |
|---|---|---|---|
| 听 | `ears/` | 音频 → 文本 | FunASR（中文强） |
| 思 | `brain/` | 认知 + 记忆 + 情绪决策 | OpenAI-compatible LLM |
| 演 | `mouth/` `face/` | 文本 → 语音 + 口型参数 | Edge-TTS + 自研元音驱动 |
| 记 | `brain/memory` | 短期/长期记忆 | SQLite + 预留向量接口 |
| 情 | `brain/emotion` | 情绪状态 + 行为决策树 | 自研（AIRI 空白区） |

## 3. 技术选型总览

| 模块 | 方案 | 理由 | 备注 |
|---|---|---|---|
| ASR | FunASR | 中文识别碾压级，阿里开源 | 较重，可降级为 `faster-whisper` |
| LLM | OpenAI-compatible SDK | 一套接口通吃 DeepSeek/通义/Kimi/本地 vLLM | 用 `base_url` + `api_key` 配置 |
| TTS | Edge-TTS | 微软免费、中文自然、零部署、秒接入 | MVP 首选，后续可换 GPT-SoVITS 克隆音色 |
| 口型同步 | **自研元音驱动** | 复现 wLipSync 思路，可解释、无模型、可扩展中文口型 | 用共振峰 F1/F2 定位元音 |
| 记忆 | SQLite | 零部署，标准库 `sqlite3` | 预留 embedding 向量接口，后续接 pgvector/Chroma |
| 情绪 | **自研 PAD + 决策树** | AIRI 无此能力，是本项目核心创新点 | valence/arousal 二维 + 意图分类 |
| 呈现 | 终端 / Web Demo | Python 不做实时渲染，渲染后置 | 后续接 Live2D SDK 或 Godot |

## 4. 各模块详细设计

### 4.1 语音识别 ASR（听）

- 输入：麦克风音频或 wav 文件
- 输出：文本
- 封装：`ears/asr.py` 定义 `ASREngine` 抽象接口，提供 FunASR 实现与 faster-whisper 备选
- 降级策略：未装 FunASR 时直接接受文本输入（demo 可跑）

### 4.2 认知与对话 LLM（思）

- 输入：用户文本 + 记忆上下文 + 当前情绪状态 + 角色设定
- 输出：回复文本 + 情绪倾向
- 封装：`brain/llm.py` 定义 `LLMEngine`，用 OpenAI SDK 兼容接口
- 提示词工程：system prompt 注入角色人设、记忆摘要、情绪状态描述

### 4.3 记忆系统（记）—— 翻译自 AIRI

AIRI 的记忆 schema（`integrations/telegram-bot/drizzle/*.sql`）翻译为 SQLite：

| AIRI 表 | 字段（关键） | Python 实现 |
|---|---|---|
| `memory_fragments` | content, memory_type, category, importance, last_accessed, content_vector(768/1024/1536) | 通用记忆片段，含重要度与向量位 |
| `memory_episodic` | event_type, participants, content | 事件记忆（「用户上次聊了 X」） |
| `memory_long_term_goals` | title, description, priority, progress, deadline, status | 长期目标 |
| `memory_short_term_ideas` | content, source_type, status, excitement(1-10) | 短期想法，excitement 即情绪强度 |
| `memory_tags` | tag ↔ fragment 关联 | 标签检索 |

两级记忆机制：
- **短期记忆**：当前会话的对话窗口（最近 N 轮），随会话重置
- **长期记忆**：跨会话持久化，按 `importance` 与 `last_accessed` 衰减/淘汰

向量预留：`content_vector` 列预留 BLOB，`MemoryStore.embed()` 钩子可接入任意 embedding 模型，后续替换为 pgvector/Chroma 的 HNSW 检索。

### 4.4 情绪模型与行为决策树（情）—— 自研

**情绪状态：PAD 二维模型**

- `valence`（愉悦度）：-1（负面）~ +1（正面）
- `arousal`（唤醒度）：-1（平静）~ +1（激动）
- 映射到离散情绪：开心(+v,+a)、生气(-v,+a)、悲伤(-v,-a)、平静(+v,-a) 等

**状态更新**：从用户输入提取情绪倾向（规则 + 可选的 LLM 判断），叠加到当前状态，并带时间衰减，使情绪「连贯但会自然平复」。

**行为决策树**（根 → 枝 → 叶）：

```
输入意图分类
├── 提问/请求信息 ──┬── 情绪偏正向 → 热情、主动补充
│                   └── 情绪偏负向 → 克制、简短但安抚
├── 闲聊 ────────────┬── 高唤醒 → 活泼、多感叹
│                    └── 低唤醒 → 温柔、慢节奏
├── 情感倾诉 ───────── 优先安抚，调用记忆共情
└── 指令/任务 ──────── 冷静执行，确认式回应
```

决策输出：语气风格参数（回复温度、称呼、口型强度、TTS 语速/音调），注入 LLM 提示词。

### 4.5 口型同步（演·口型）—— 复现 wLipSync

**AIRI 思路**：音频流 → 元音 A/E/I/O/U + 静音的权重 → 口型参数（Live2D `ParamMouthOpenY` / VRM blend shape）。

**Python 复现**（离线，从 TTS 生成的 wav）：

1. 读 wav → 分帧（25ms 帧 / 10ms 跳）+ 加窗
2. 每帧用 LPC 提取前两个共振峰 F1、F2
3. 共振峰 → 元音定位（元音四边形规则）：

| 元音 | F1 (Hz) | F2 (Hz) | 张嘴幅度 (0-1) |
|---|---|---|---|
| /a/ 阿 | 700–850 | 1200–1400 | 1.0 |
| /e/ 诶 | 400–550 | 1800–2200 | 0.5 |
| /i/ 衣 | 250–350 | 2200–2800 | 0.3 |
| /o/ 哦 | 450–550 | 800–1000 | 0.6 |
| /u/ 乌 | 300–400 | 600–900 | 0.35 |

4. 音量包络加权 + 静音检测（低于阈值 → 闭嘴）
5. 平滑：移动平均 + `applySustainedMouthClosure`（长句强制自然停顿闭嘴）

**输出**：每帧 `mouth_open`(0-1) + `vowel`(当前元音) 序列，可对接 Live2D `ParamMouthOpenY` 或任意渲染层。

> 差异化：AIRI 仅英语元音；本方案可扩展中文元音（a/o/e/i/u/ü）与声调，作为项目创新点。

### 4.6 语音合成 TTS（演·声音）

- 输入：回复文本 + 情绪参数（语速、音调）
- 输出：wav 文件
- 封装：`mouth/tts.py` 定义 `TTSEngine`，Edge-TTS 实现；情绪参数映射到 `rate`/`pitch`

## 5. AIRI 算法翻译对照表

| AIRI 能力 | AIRI 实现 | 本方案 Python 实现 | 差异 |
|---|---|---|---|
| 口型同步 | wLipSync（英语元音 AEIOU） | 共振峰 F1/F2 元音定位 | 支持中文、可解释 |
| 记忆存储 | DuckDB WASM / pglite | SQLite（sqlite3） | 更成熟、可迁向量库 |
| 记忆检索 | HNSW 向量（未完成） | 预留向量接口 + 关键词/SQL | 先跑通，后升级 |
| 情绪/表情 | 仅眨眼/注视/idle | PAD 情绪 + 行为决策树 | **新增，AIRI 空白区** |
| TTS | ElevenLabs/Azure/Kokoro 等 | Edge-TTS | 中文免费零部署 |
| ASR | 浏览器/Discord 客户端 | FunASR | 中文更强 |
| 渲染 | WebGPU/Live2D/VRM | 后置，终端/Web Demo | 分期实现 |

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| FunASR 依赖重、首次跑需下载模型 | 提供 `faster-whisper` 降级 + 文本直连模式 |
| 共振峰元音定位对噪声敏感 | 静音检测 + 平滑 + 能量加权；预留可替换的音素分类接口 |
| Edge-TTS 依赖网络 | 可缓存音频；后续换本地 GPT-SoVITS |
| 向量检索初期无 embedding | 先 SQL 关键词检索，embedding 接口预留 |
