# DOC-002 · 技术计划中的向量及音频接口规格过期

- **等级：** P2 · 中（设计参考错误）
- **状态：** 静态代码与文档交叉确认
- **置信度：** 高

## 摘要

`docs/技术选型与模块重写计划.md` 目前没有标记为历史版本，读者容易把它当作当前设计依据。但其中向量检索状态、TTS 文件格式和语音链路接口至少三处与当前实现不同。

## 证据

- 第 41、52、88、151、174 行仍把向量存储/检索称为“预留”或“未完成”；而 `src/avatar/brain/memory.py` 已实现可选 embedder、向量索引与余弦检索，`docs/backend.md` 说明了 Ollama 配置与回退行为。
- 第 142 行明确写 TTS 输出 WAV；`src/avatar/mouth/tts.py` 的类文档和 `synthesize()` 明确输出 MP3。
- 第 60 行把 ASR 输入描述为麦克风或 WAV；当前 `ASREngine.transcribe(audio_path)` 是文件路径协议，FunASR 对路径调用 `generate()`，没有麦克风采集 API。
- 第 118–138 行把 TTS WAV 到逐帧口型的方案当作实现流程；实际 `Avatar` 未将 TTS 文件加载并传入 `LipSyncEngine.analyze()`，也不在响应对象中返回口型帧（见既有 AUD-004）。
- 第 163 行将 M3 标成“语音进出闭环”，与当前组件存在但主流程未完成集成的状态混淆。

## 影响

维护者可能基于 WAV 假设构建调用方、认为麦克风输入已经有接口，或在已有语义检索上重复选型。计划文档中的架构图和里程碑也无法作为当前验收标准。

## 修订建议

将文档显式标成“初始技术方案 / 历史设计”，或更新为当前接口规格；对 ASR、TTS、口型分别区分单模块 API 与 Avatar 端到端集成状态。记录 TTS 实际 MP3 输出及转 WAV 的外部依赖/限制。将向量部分改为当前可选能力说明。
