结论摘要

当前主要风险在于：危险情绪规则对混合时间表达存在漏判路径；联网工具的提醒写操作没有与当轮用户请求绑定；Python 3.10/3.11 环境的资料搜索会调用不存在的 API。另有记忆空词召回、全静音口型输出、语音组件未接入主流程及本机 Web 单线程阻塞等问题。

审计边界：本轮只做静态代码、已有测试和文档交叉核对。没有运行全量测试、真实模型、联网写工具、ASR/TTS 或设备流程。问题记录均标明证据性质；需要运行时复现的项不能视为已经验证修复。
建议顺序：先封住未经明确请求的提醒写操作并修复当前风险漏判；同时解决 Python 兼容。之后修复检索/静音确定性缺陷，再排语音链路、Web 响应隔离和情绪时间参数标定。

优先修复策略

  1. P1 安全与授权：AUD-001 按分句判断历史/当前时间作用域；AUD-002 在执行器做写授权，不以提示词代替校验。
  2. P1 兼容性：AUD-003 用 Python 3.10 可用的 junction 检测兼容层，增加最低支持版本下的目录树检查。
  3. P2 确定性行为：AUD-005 增加全静音早退；AUD-006 区分无查询与有查询但无 token。
  4. P2 集成与可用性：AUD-004 明确组件/端到端完成状态并制定统一音频—口型 API；AUD-008 设置明确请求超时并隔离长任务与提醒轮询。
  5. 设计校准：AUD-007 先明确目标半衰期，再调整默认值并用模拟时钟锁定行为。

修复时应为每个问题建立专属回归用例；安全路由、数据库状态、工具副作用和语言质量应分开验收。这里是建议，不代表本次已修改生产代码。
