# AUD-002 · 提醒写工具没有绑定当前用户请求

- **等级：** P1 · 高
- **类别：** 工具授权 / 本机数据完整性
- **状态：** 静态调用链确认；未执行有副作用的复现
- **置信度：** 高

## 摘要

联网工具规划阶段会把 `create_reminder` 与 `cancel_reminder` 一起提供给模型。执行前的参数检查只确认创建文本以“提醒我”开头、取消编号是正整数，没有验证当前用户是否真的要求创建/取消，也没有把创建文本与当前消息原文核对。因此，当用户只勾选本轮联网工具并提出搜索等请求时，模型误调用或被对话内容诱导调用，仍可能创建或取消本机提醒。

## 证据

- `src/avatar/tools/web_agent.py:32-35` 将两个写操作作为普通可选工具暴露。
- `src/avatar/tools/web_agent.py:37-39` 的 system 提示要求按本轮请求规划，但它只是模型提示，不是授权检查。
- `src/avatar/tools/web_agent.py:238-268` 接受模型给出的工具调用并执行 `REGISTRY.validate()` 后调用 MCP；验证器没有接收 `user_text`。
- `src/avatar/tools/web_agent.py:83-92` 的创建校验只要求文本匹配 `提醒我` 前缀，取消校验只要求正整数编号。
- `src/avatar/tools/assistant_server.py:33-50` 最终直接创建/取消 SQLite 提醒，也没有用户原请求上下文可供校验。
- `ToolSpec.write` 在 `web_agent.py:109` 被赋值，但仓库中没有执行该标记、限制写权限的代码。
- `tests/test_web_agent.py:120-127` 只验证不以“提醒我”开头的文本被拒绝；没有验证有效格式的伪造提醒必须与当前请求相符。文档声称写操作须由用户明确要求，但当前执行路径没有强制实现这一点。

## 影响

这会把可写本机提醒的能力委托给模型判断。模型的工具选择错误、上下文误读或外部网页内容影响，都可能造成未经用户本轮明确授权的提醒创建/取消。其影响限于提醒数据，但违反“明确指令才写入”的产品承诺。

## 建议

1. 在 `WebAgent`/工具执行器层增加确定性授权判断；不要只依赖 system prompt 或 tool description。
2. 创建提醒时要求当前原始用户消息本身通过提醒语法解析，并确保 MCP 参数与该原文一致；不允许模型补造“提醒我……”文本。
3. 取消提醒时要求当前请求明确表达取消意图，并把目标编号绑定到用户明确选择的提醒；对不明确的目标先询问。
4. 写操作单独记录 `authorized_by_user_request`、原始请求和执行结果；未授权调用在到达 MCP/SQLite 前拒绝。
5. 在测试中用一个无关搜索请求配合“格式有效”的伪造创建参数，以及一个非取消请求配合有效 ID，断言两者均不触发数据库写入。

## 验收建议

- 无明确创建/取消意图时，写工具即使被模型调用也不会执行。
- 用户明确请求创建时，只有当前用户原文中可验证的日期、时间、事项会进入存储。
- 仅在实际执行写操作后返回成功状态；拒绝路径有独立状态和可审计原因。
