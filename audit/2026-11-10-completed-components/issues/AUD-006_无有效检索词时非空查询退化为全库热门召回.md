# AUD-006 · 无有效检索词时，非空查询退化为全库热门召回

- **等级：** P2 · 中
- **类别：** 记忆召回相关性
- **状态：** 静态控制流确认；未运行 SQLite 示例
- **置信度：** 高

## 摘要

`_lexical_recall()` 只在 `_tokenize(query)` 结果非空时执行关键词匹配；若用户查询非空但全部由停用词组成（例如“嗯”“你还记得吗”），控制流会落入“无查询”分支，按重要度返回全库高分记忆。这个分支本来适用于 `query=None` 或空字符串的列表浏览，不适用于已提供但无法提取检索词的查询。

## 证据

- `src/avatar/brain/memory.py:137-142` 用停用词替换切词；命中停用词后 `_tokenize('嗯')` 返回空列表。
- `src/avatar/brain/memory.py:414-428` 只在 `if tokens:` 时执行关键词过滤；空 token 继续下落。
- `src/avatar/brain/memory.py:430-439` 空 token 分支不加内容条件，按 `importance` 与 `last_accessed` 返回全库记录。
- `src/avatar/brain/memory.py:375-399` `recall(query=非空文本)` 会把这批全库结果当作本轮 lexical 候选；向量关闭时直接返回，向量开启时也会混入排序。
- `tests/test_memory.py` 覆盖了显式无 query 的列表/召回场景，没有覆盖非空但无有效词的 query。

## 影响

短回应、寒暄、只含停用词的查询会把与当前话题无关的记忆标记为本轮召回，并可能进入 system prompt 或 UI 的召回编号。这会造成不相关个性化、召回反馈噪声，并让“无匹配”与“全库重要记忆”无法区分。

## 建议

1. 区分 `query is None/空白` 与“非空查询但分词结果为空”。前者可保留全库排序，后者应返回空 lexical 候选。
2. 有 embedding 时仍可单独执行语义召回；没有 embedding 时明确返回“无检索词/无匹配”，不要伪装成无 query。
3. 把纯停用词、短寒暄、只有标点、以及正常有区分度的中文 query 纳入召回相关性测试。

## 验收建议

- `recall(query=None)` 仍可按预期列出重要记忆。
- `recall(query='嗯')` 在关键词模式下返回空结果。
- 有有效关键词的查询排序行为保持不变；语义模式中的语义候选不被错误清除。
